# バズ企画リサーチ（buzz-kikaku-research）｜手が止まった1本 → 本物か判定 → なぜ伸びたか仮説 → 自分の企画へ

## このスキルについて

バズリサーチの「ジャッジ役」を肩代わりするスキル。役割分担が核：

- **ユーザー（受講生）＝センサー役**：発見欄をスクロールして「なんか手が止まった」を感じてURLを持ってくる。ここは本人にしかできない
- **このスキル＝ジャッジ役**：本物のバズか数字で判定 → 伸びてる群/伸びてない群の冒頭7秒を比較して仮説カード発行 → 他アカウントで検証 → 自分の企画への落とし込み

**毎回、判定に使った数字とルールを全部見せる。** 受講生が使うたびに判断軸そのものが身につく「教材としても機能する報告書」がこのスキルの価値。

**分析は冒頭7秒だけ。** 全編は見ない（教材の思想：リールは1〜2秒で手を止めるか、次の5秒で見続けるかが決まる。最後まで見て分析する時間を冒頭の言語化に使う）。

**使い分け（重要）:**
- このスキル → 「この投稿/アカウント、参考にしていい？」の判定＋「なぜ伸びてる？」の仮説立て。横断・冒頭特化
- `bunseki-reel` → 合格した1本を丸ごと深掘り（全編・構成・台本・CTA）
- `bunseki-competitor-account` → アカウント丸ごと徹底分析（プロフィール＋台本全文）
- `concept-research` → コンセプト設計段階の「ジャンル×企画」横断リサーチ（コンセプトの材料集め）。こちらは運用中に見つけた投稿のバズ判定＋フック仮説
- `threads-buzz-research` → Threads専用。このスキルはInstagramリール専用

## 判定基準（このスキルの憲法。全ステップでこれに従う）

出典: バズリサーチの定石（参考教材）＋けんじ式アカウントランク。

1. **バズ認定ライン** = 再生数がフォロワー数の**10倍以上**、または**100万再生以上**
   - 例: フォロワー3万人 → 30万再生以上で合格。フォロワー50万人で60万再生 → 1.2倍なので不合格
2. **影響力型の罠** = どの投稿も満遍なく高く、アカウント内に突出した投稿がない人（有名人・インフルエンサー）は「本人の人気」で回っている → **企画・フックの参考にしない**
3. **アカウントランク**：
   - **S級** = 少ない投稿でバズを量産している（目安: バズ5本以上×バズ率20%以上。例: 10投稿でフォロワー1万・うち5〜6本が10〜30万再生）→ 再現性が高いお宝アカウント。**バズ投稿を全本分析**して伸びる理由を確実に言語化する
   - **通常** = バズ1〜4本 → その全部を分析
   - **影響力型** = 分析しない（理由を教育的に説明）
4. **バズる理由は3つしかない**：**ビジュアルフック**（目を引く冒頭映像）／**サウンドフック**（BGM・効果音・ASMR）／**バーバルフック**（刺さる一言）、またはその組み合わせ
5. **バーバルフックの7トリガー**：①検証企画（どうなるの？）②常識破壊（なんで⁉）③ビフォーアフター（どうやったの⁉）④権威×論争 ⑤プライベート公開（具体的な数字ほど強い）⑥結末予想不能 ⑦ランキング（1位は何？）
6. **仮説の確度**：**A** = 複数アカウントで再現 ／ **B** = 1アカウント内のみ（本人が気づいてないだけの可能性あり＝有望）／ **C** = 単発・弱い。**見つからないのにAにしない（幻覚厳禁）**

## STEP 0：入口判定 — URLが無ければ「探し方ガイド」を出す

ユーザーの入力を見て分岐する：

- **リールURLあり**（`instagram.com/reel/…` または `/<user>/reel/…`）→ STEP 1 へ。あわせて**「なんで手が止まったか、一言でいいので教えて」**と聞く（分析と並行でよい。答えは仮説①としてSTEP 3で答え合わせする。「わからない」でもOK：「映像？音？言葉？のどれに反応したかだけでも」と3フックのレンズを添える）
- **アカウントURLのみ** → 提出リールなしモードでSTEP 1へ（アカウント全体の判定と仮説立てを行う）
- **URLなし**（「バズ企画リサーチしたい」だけ等）→ 以下の**探し方ガイド**をチャットで出して、持ち帰ってもらう：

> **🔍 こういうものを探してきてください（発見欄スクロール時の目のつけどころ）**
> 1. 場所は**自分の発見欄**（リールタブではなく）。スクロールして「なんか手が止まった」ものが候補
> 2. 手が止まったら、その投稿の**再生回数**と発信者の**フォロワー数**をチェック：
>    - ✅ **再生回数がフォロワー数の10倍以上** → 合格ライン（例: 3万人のアカウントで30万回なら合格）
>    - ✅ **100万再生以上** → 文句なし
>    - ❌ フォロワー50万人で60万回 → 1.2倍なので実はバズってない
> 3. ⚠️ **どの投稿も満遍なく伸びている有名人は避ける**（本人の人気で回っているだけで、企画の参考にならない）
> 4. **迷ったらとりあえずURLを貼ってOK**。合否判定はこっちで数字を見てやります
>
> 見つけたらリールのURL（共有ボタン→リンクをコピー）を貼ってください。**「なんで手が止まったか」の一言**も添えてもらえると、あなたの感覚の答え合わせまでできます

- **「ネタ帳から出して」等** → STEP 8 のネタ帳モードへ

## STEP 2：バズ判定 — フォロワー数とリール一覧を収集して機械的にジャッジ

### 2-1. プロフィール収集

`navigate` で `https://www.instagram.com/<username>/` へ。スクショで状態確認（未ログイン→ログインを案内して終了／非公開→見られない旨伝えて終了）。`get_page_text` でフォロワー数・投稿数・表示名・bioを控える。

### 2-2. リール一覧の収集（既知の罠に注意）

`https://www.instagram.com/<username>/reels/` へ移動。**制約4つ**：

1. navigate直後はグリッド未描画で href が0件になる。**2〜3秒待ってから**収集。0件でも構造を疑う前にまず待って再実行（ハイドレーションが遅いだけのことが多い）。**それでも0件ならリールタブのアイコンをクリックして3秒待つと描画されることがある**（実測済み）
2. リールのリンクは `/<username>/reel/<ID>/` 形式（`a[href*="/reel/"]` で拾える）
3. 再生数テキストは「カウントアイコンを見る29.7万」のようにラベル付き。ラベルを除去して数字だけ抽出
4. サムネのCDN URLはツール結果に含めるとBLOCKEDされる。**パス・再生数・ピン留めだけ**をJSONで返す

グリッドは仮想化されているので、`javascript_tool` でアキュムレータに溜めながらスクロール：

```js
window.__ig = window.__ig || {};
document.querySelectorAll('a[href*="/reel/"]').forEach(a => {
  const key = a.href.split('?')[0];
  if (key.endsWith('/reels/')) return;   // ナビリンクを除外
  const m = (a.textContent || '').replace(/カウントアイコンを見る/g, '').trim().match(/^[\d.,]+(万|億|千)?/);
  if (!window.__ig[key]) window.__ig[key] = {views: m ? m[0] : '', pinned: !!a.querySelector('svg[aria-label*="固定"], svg[aria-label*="Pinned"]')};
});
window.scrollBy(0, window.innerHeight * 2);
Object.keys(window.__ig).length
```

- 件数が増えなくなっても即打ち切らず、**ゆっくり小刻みスクロール（画面の0.6倍ずつ・2〜3秒待ち）＋たまに上下に揺らす**を数回粘る。1回のJS実行は30秒以内に収める（長いループはタイムアウトする）
- **PC版IGは古いリールを出し渋ることがある**（実測: 33投稿のアカウントで直近24本までしか読み込まれず、それより古い投稿はスクロールしても出ない）。粘っても増えない場合は「直近◯本まで」と正直に記録して先へ進む。**一覧圏外の古いバズはユーザーのスマホには見えている**ので、「古いバズを知っていたらURLを貼って」と促し、下記のいいね率推定で個別判定する（提出ベースで網羅性の穴を埋める設計）
- 収集を連打しすぎるとグリッド自体が描画されなくなる（レートリミット）。その状態になったら数分置く。DL・スクロールの間隔を詰めない
- 最後に `JSON.stringify(Object.fromEntries(Object.entries(window.__ig).map(([u,v]) => [new URL(u).pathname, v])))` で取り出し、`data/reels.json` に `{"https://www.instagram.com/<user>/reel/<ID>/": {"views": "12.3万", "pinned": false}}` のフルURL形式で保存
- 再生数が全部取れない（非表示）場合は止まらず、その旨を報告書に正直に書いて、提出リール1本＋最新数本の冒頭分析だけの縮退モードで続行

**提出リールが古くてグリッド圏外（再生数が見えない）場合の推定手順（実測済み）:**
1. 再生数が判明している3〜4本のいいね数を取得: `<venv-python> -m yt_dlp --skip-download --print "%(id)s likes=%(like_count)s" "<リールURL>"`（1本ごとに3秒空ける）
2. いいね率＝いいね÷再生数 のレンジを実測（例: 1.1〜2.0%）
3. 提出リールのいいね数（fetch_head の meta.json に入る）をそのレンジで割り戻し、**推定再生数のレンジ**を出す
4. 判定・報告書では必ず「推定」と明示し、推定方法（いいね率からの逆算）も報告書に書く＝これ自体が判断軸の教材になる。古い投稿は投稿時のフォロワーが今より少なかった可能性（＝実際の倍率はさらに高い）も添える

### 2-3. 機械ジャッジ

```bash
python3 <skill>/scripts/buzz_judge.py <out>/data/reels.json <out>/data --followers <フォロワー数（65.8万 形式OK）> --posts <投稿数> --submitted "<提出リールURL（あれば）>"
```

`judge.json` とサマリーが出る（バズ認定ライン・バズ本数・ランク・提出リールの合否・分析対象の選定まで全部入り）。判定はスクリプトの数字が正。**ここで一度ユーザーに経過報告する**（例:「フォロワー1.2万・バズ認定ライン12万。収集32本中バズ7本＝S級アカウントです🔥 提出リールは38万再生＝フォロワー比31倍で文句なしの本物。これから伸びてる群7本＋伸びてない群4本の冒頭7秒を比較します」）。

**分岐：**
- **影響力型** → 分析せず終了。なぜ参考にならないか（数字つき）＋「その投稿で使われている企画を、フォロワーが少ないアカウントでもやって伸びている人がいれば、それは企画が強い証拠。そういうアカウントを探すか、別の手が止まった投稿を持ってきて」と次の行動を案内。報告書は作らない（チャット説明のみ）
- **バズなし** → 提出リールが不合格の場合も「なぜ不合格か」を数字で説明し、探し方ガイド（STEP 0）を再提示。無理に分析しない
- **合格** → STEP 3へ

### 2-4. 感謝コメントの確認（企画需要の補助シグナル）

提出リール（またはバズ1位）のページでコメント欄を開き、「参考になりました」「わかりやすい」系の感謝コメントがあるか確認。あれば「情報そのものに価値がある＝企画が強い」の補助証拠として報告書に記載（なくても減点にはしない）。

## STEP 3：冒頭7秒の取得と共通点分析

### 3-1. 取得（伸びてる群＋対照群を全部）

`judge.json` の `analyze`（伸びてる群）と `control`（対照群）の各URLについて：

```bash
<venv-python> <skill>/scripts/fetch_head.py "<リールURL>" "<out>/reels/<ID>" --language ja
```

- 1本あたり: 動画DL → 冒頭フレーム6枚（0.3/1/2/3/5/7秒）→ 冒頭12秒だけ文字起こし。軽い
- 複数本は**バックグラウンドで直列に流し**、待ち時間に完了した本からフレームをReadして分析を進める
- DL間隔を詰めない（IGレートリミット・BAN回避）。一部失敗しても続行し、失敗分は報告書に正直に書く

**文字起こしの注意（最重要）：** 冒頭がBGMのみのリールでは文字起こしが空・幻覚（「ご視聴ありがとうございました」の繰り返し等）になる。`head_transcript_warning` が出ていたら**文字起こしを結論に使わず、フレームの口の動きとテロップで裏を取る**。「ナレーション無し」と断定してよいのはフレームで確認できたときだけ。壊れた出力から結論を出さない。

### 3-2. 共通点の抽出（このスキルの頭脳）

全本の冒頭フレームをReadし、文字起こしと合わせて、**1本ごとに冒頭7秒の要素表**を作る：

- **映像**: 0〜2秒に何が映るか（モノ・人・動き・世界観・テロップの有無と文言）
- **色味・おしゃれさ**（見落とし注意・必須列）: カラフルか単色か、原色POPか淡色か、画面の何割を占めるか。**インスタはカラフルなインテリア・物・おしゃれなものが伸びやすい傾向がある**ので、色は独立した要素として必ず記録する
- **音**: ナレーション有無・最初の一言・BGMの種類・効果音/生活音の強調
- **言葉**: 冒頭ワード（音声＋テロップ）。7トリガーのどれに当たるか

⚠️ **共通点を単一ラベルに丸めない。** 見つけた要素は構成要素に分解して全部書く。例:「キャラ食器が伸びてる」で止めず「①国民的キャラ（認知度） ②POPな原色カラー ③画面占有が大きい ④注ぐ動作とセット」に分解する。受講生が自分で再現するとき、どの成分が効いているかで作るものが変わる。丸めると受講生も同じ要素を見落とす。

**抽象度違いの競合仮説を並走させる（けんじ式・重要）:** 分解した成分から、抽象度の違う仮説を2〜4本セットで出し、**この時点でどれが正解か決めない**。例:
- A「クレヨンしんちゃん×カラフル」（最も具体）
- B「カラフル」（最も抽象）
- C「国民的キャラ×カラフル」（中間）

その後の検証（アカウント内の他の投稿・横断検証・次回以降のリサーチ）で伸びてる例が新しく見つかるたびに「A/B/Cのどれにハマるか」を記録し、**ハマる例が増えた仮説を「再現性が高い」と判断して残す**。切り分けに効く事例は特に価値が高いので明記する（例: しんちゃん以外の国民的キャラで伸びてる例→C支持・A棄却／キャラ無しのカラフル小物だけで伸びてる例→B支持）。仮説カード・ネタ帳にも競合仮説をセットのまま書き、検証のたびに票を付けていく。

そして**「伸びてる群に共通していて、伸びてない群に無い要素」**を探す。これが仮説候補：

- 判定は保守的に。「6本中5本にある／対照群4本には無い」のように**分母つきで**数える
- 例外があれば無視せず記録（「#3だけは違うが伸びている→別要素の可能性」）
- ユーザーの「手が止まった理由」（仮説①）と照合し、当たり/ズレを明示（感覚のキャリブレーション。ズレていても「その感覚も◯◯という点では正しい」と拾う）

**仮説カードの形式**（1〜3枚が目安。無理に3枚作らない）：

```
仮説: 「タンブラーはポップなカラーのものが共通して伸びている」
フック種別: ビジュアルフック（バーバルなら7トリガー名も）
根拠: 伸びてる群6本中5本の0〜2秒にカラフルなタンブラー／伸びてない群4本は白・黒
反証・注意: #3は白でも伸びている→湯気の接写も効いている可能性
確度: B（このアカウント内でのみ確認）
```

## STEP 4：横断検証 — 他のアカウントでも起きているか（半自動）

仮説の確度をB→Aに上げる工程。**やれる範囲で正直に**：

1. **ユーザー提供が最優先**：「同ジャンルで知ってる競合アカウントある？」と聞き、もらったURLで検証（STEP 2の収集→バズ投稿の冒頭に同じ要素があるかだけ確認。フレーム数枚でよい）
2. **自動探索**：IGの検索（ジャンル名・企画キーワード）で同ジャンルのアカウントを1〜2個探し、そのバズ投稿（同じ基準: FW×10 or 100万）の冒頭に同じ要素があるか確認
3. **ネタ帳との照合**：ネタ帳.md に同じ要素の過去仮説があれば、それも再現例としてカウント（別アカウント由来ならB→A昇格）

**確度の付け方：** 別アカウントのバズで再現＝A／このアカウントのみ＝B／1本だけ＝C。**再現が見つからなくてもBのまま正直に出す**（教材の注意点：共通点が無い＝要素でない、とは限らない。本人が気づいていないだけの可能性がある）。検証しきれなかった旨と「競合URLをくれれば追加検証できる」ことを報告書に書く。

## 注意事項

- ダウンロード・スクロール間隔を詰めない（IGレートリミット・BAN回避）
- 収集した動画・画像は研究目的のローカル保存。転載しない（報告書フッターの注意書きで足りる）
- **数字の創作・仮説の水増し禁止**。判定は buzz_judge.py の数字が正。確度Aは再現を実際に確認したときだけ
- 壊れた文字起こし・空の収集結果から結論を出さない。「対象がそう」ではなく「取得が壊れた」をまず疑い、フレーム・別ソースで裏を取る
- 影響力型アカウントを分析対象にしない（受講生が一番ハマる罠。必ず数字つきで教育的に説明する）
- 途中で何かが失敗しても報告書（またはチャット報告）を最後まで届けることを最優先。失敗は隠さず書く
- メモリにあるけんじ個人や他人のアカウント名を報告書に勝手に書かない（受講生配布で他人の情報が混ざるため）
