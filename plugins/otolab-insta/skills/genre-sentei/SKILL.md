# genre-sentei｜ジャンル選定

## このスキルについて

ジャンルは「好き・やりたい」ではなく**市場の数字で決める**もの。このスキルは4スキル連携の2番目を担う：

```
insta-concept-design（自己分析・ジャンルの種） → genre-sentei（本スキル・戦うジャンル確定） → concept-research（ジャンル内の企画リサーチ） → concept-brush-up（決定版）
```

流れは6ステップ。STEP 2の途中で**ユーザーのスマホ巡回待ちのため一旦停止する**のが正常な動作。

| STEP | 内容 | 詳細指示書 |
|---|---|---|
| 0 | 引き継ぎ＋現在地判定（パターン①／②の分岐） | 本ファイル |
| 1 | 候補ジャンル出し（2〜3個） | 本ファイル＋`references/genre-85sen.md` |
| 2 | 市場調査（2A: Chromeでトップ層調査／2B: スマホ巡回宿題→**停止**／2C: 統合・Go/No-Go判定） | `references/research-criteria.md` |
| 3 | 収益化導線チェック＋ずらし導線設計 | `references/research-criteria.md` |
| 4 | 落とし穴チェック＋1ジャンルに確定 | 本ファイル |
| 5 | HTML報告書＋genre_sentei.md 出力 | 本ファイル＋`assets/report_template.html` |

**該当STEPを始める前に必ず対応する指示書を読むこと。** 判定基準はすべて数値で書いてある。感覚で判定しない。

## 中断・再開の仕組み（最初に理解しておくこと）

- 出力フォルダに `genre_state.md` を置き、STEP進行のたびに更新する。記録内容：現在のSTEP／パターン①か②か／候補ジャンル／収集済みデータ／待ち状態（例:「2B提出待ち」）
- スキル起動時は**まず既存の `genre_state.md` を探す**：`~/Documents/Claude/Projects/インスタコンセプト設計/` 配下の `<対象者名>_ジャンル選定_*` フォルダ。見つかったら状態を読んで続きから再開する
- ユーザーがアカウントのリンクやスクショを貼ってきたら、それは2Bの提出物。2Cから再開する
  - ※concept-research にも同じ提出制の宿題がある。どちらの提出かは、提出待ち状態のstateファイルがどちらのフォルダにあるかで判定する

## 出力フォルダ

```
~/Documents/Claude/Projects/インスタコンセプト設計/<対象者名>_ジャンル選定_<YYYYMMDD>/
├── genre_state.md           ← 進行状態（常時更新）
├── 01_候補ジャンル.md        ← STEP 1 の確定内容
├── 02_巡回宿題.md           ← STEP 2B でユーザーに渡した指示書の控え
├── 03_ジャンル選定報告書.html ← STEP 5 の本体
└── genre_sentei.md          ← concept-research への橋渡しファイル
```

## STEP 0：引き継ぎ＋現在地判定（パターン分岐）

1. `~/Documents/Claude/Projects/インスタコンセプト設計/` から対象者の初期設計フォルダ（`<名前>_<日付>/`）を探して読む。複数あれば対象者名を確認
   - `01_自己分析レポート.md`（「発信できそうなジャンルの種」「独自性素材シート」のセクションが最重要）
   - `02_コンセプト3案.md` があれば、★採用案のジャンルを「候補ジャンルの1つ」として市場で検証する（＝仮説の裏取りだと明示する）
2. Webアプリ利用者（受講生）は成果物をテキストで持っている。ファイルがなければ「初期設計の結果をコピペしてもらえますか？」と案内。初期設計なしでも動ける
3. **最初の分岐質問（このスキルの核）**：「売りたいものや、やりたい収益化の形は決まっていますか？」
   - **パターン①：まだ決まっていない** → 必ずこう伝える：「それが普通です。ほとんどの人がここからのスタートなので、始められない理由には1ミリもなりません」→ STEP 1 の①ルートへ
   - **パターン②：明確に決まっている** → 売りたいもの・ゴールを具体的に聞く → STEP 1 の②ルートへ
4. 不足がある場合のみヒアリング（**1問ずつ**）：毎日の生活・仕事でやっていること／過去の悩みと乗り越えた経験／人からよく相談されること／興味があって普段調べていること

## STEP 1：候補ジャンル出し（2〜3個に絞る）

`references/genre-85sen.md`（ジャンル引き出しリスト）を読んでから進める。

- **①ルート（売りたいものがない人）**：自己分析の棚卸しから「発信の種」を拾い、引き出しリストと突き合わせて候補を出す。本人の生活・経験から出てこないジャンルを押し付けない
- **②ルート（売りたいものが明確な人）**：売りたいものから連想で関連ジャンルを広げる。直接関連だけでなく**届けたい相手が重なるジャンル**まで広げてよい（例: ショート動画教材→動画編集→撮影→写真の撮り方）。広げ方の実例は genre-85sen.md の末尾にある
- どちらのルートも、候補にする前に**継続の事前チェック**を対話で行う（1問ずつ）：
  - 「これは生活導線上にありますか？（どうせ毎日やることの"ついで"に撮れますか？）」
  - 「**100投稿できるイメージが湧きますか？**」
  - 基準の意味は失敗実例で伝える：「カフェ紹介のアカウントを続けるには土日に7軒回る必要があって、続かずやめてしまった人がいます。毎日の自炊のついでに撮れるレシピに変えたら続いた、という話です」
- **今すぐ実績がなくても候補にしてよい**。「挑戦している過程」もリアルであるほど良いコンテンツになる（実績が必要なジャンルの扱いはSTEP 4で判定する）
- 候補2〜3個を `01_候補ジャンル.md` に保存し、genre_state.md を更新

## STEP 2：市場調査（心臓部）

**開始前に必ず `references/research-criteria.md` を読む。** 数値基準・手順・罠の全てがそこにある。

- **2A（Chromeでトップ層調査）**：候補ジャンルごとに、Claude in ChromeでInstagramを**検索ベース**で巡回し、トップ層アカウント（情報発信メイン）のフォロワー数を記録する。PCのおすすめ欄・発見欄は精度が悪いので**使わない**
- **2B（スマホ巡回の宿題）**：「直近伸びているアカウント探し」は発見タブの育成が必要＝**スマホでしかできない**。`references/smartphone-homework.md` の指示書をユーザー向けに具体化して渡し、**スキルはここで一旦停止**。指示書の控えを `02_巡回宿題.md` に保存、genre_state.md を「2B提出待ち」にして終了
- **2C（統合・Go/No-Go判定）**：提出が来たら再開。候補ジャンルごとに数値基準で判定表を作り、Go（合格）／No-Go（見送り）／条件付きGo（特化すれば可）を根拠つきで提示する

## STEP 3：収益化導線チェック＋ずらし導線設計

`references/research-criteria.md` の後半に従う。2Cを通過した候補ジャンルごとに：

1. 先駆者のプロフィール・ハイライト・タイアップ投稿をChromeで確認し、「**この人は何で収益化しているか**」を具体的に記録する。見つからないジャンルは危険信号として明示
2. **ずらし導線**を1〜2案設計する：「投稿＝伸びやすいジャンルでパイを取る × ストーリーズ＝収益化したいジャンルを発信」の組み合わせ
3. パターン②の人は「売りたいものへの自然な橋」を言語化する
4. 収益化の話で不安にさせない。「先駆者が収益化しているのを確認できて、イメージが湧けばOKです。考えすぎて動けなくなるのが一番もったいないです」と必ず伝える

## STEP 4：落とし穴チェック＋1ジャンルに確定

最終候補に対して3つの落とし穴を対話でチェックする（**1問ずつ**）：

1. **「伸びてるから」だけで選んでいないか**：「このジャンル、調べること自体は楽しめそうですか？」— 数字が良くても本人が興味を持てないなら外す。正解は「**伸びているジャンル×自分が続けられるジャンルの重なり**」
2. **見切り発車になっていないか**：実績・証拠が必要なジャンル（ダイエット・ビジネス・スキル系）で今の本人に見せられるものがない場合、**期限付き準備期間プラン**を提案する：
   - 最短1ヶ月・最長2ヶ月と期限を明確に決める（期限なしの「いつか準備できたら」は永遠に始まらない）
   - 期間中は毎日30分〜1時間のインプット or 実践＋素材の撮り溜め（ビフォーアフター写真など）
   - 期限が来たら完璧でなくても必ず始める
   - 実例を添える：「2ヶ月発信を止めてダイエットを実践し、ビフォーアフター素材を撮り溜めてから始めた人は、20投稿以内に1万人を達成しています」
3. **ブルーオーシャンに逃げていないか**：競合がほぼいないジャンルは、本人に専門家級の実績・資格がない限り選ばない。「競合が多い＝需要がある証拠でチャンス。競合ゼロのジャンルはそもそも誰も見ていない可能性が高いです」と明示

確定の手順：
- 3つの掟チェックリスト（**需要がある・継続できる・収益化できる**）が全部✅のジャンルだけを最終候補にする
- 迷ったら「より継続しやすい方」「収益化のイメージがより具体的な方」を勧める
- 最後は**本人に選んでもらう**：「この数字を見て、自分が続けられそうなのはどれですか？」（AIが確定しない）
- 確定したら、そのジャンル内の**特化テーマの方向性**（例:「レシピ」→「冷凍ストック×簡単レシピ」）まで軽く目星をつける。深掘りは concept-research の仕事なので、ここでは方向性1行でよい

## STEP 5：成果物の出力

1. `assets/report_template.html` をベースにHTML報告書を生成（デザイン・配色はテンプレートのまま変えない）。構成：現在地／候補ジャンルの判定結果（数値バッジつき）／見つけたアカウント一覧／収益化導線マップ／確定ジャンル／（該当者のみ）準備期間プラン／次の一歩
2. `03_ジャンル選定報告書.html` に保存し、Claude in Chrome の navigate で `file:///...` を開いて見せる（Chrome拡張が使えなければ `open <パス>`）
3. `genre_sentei.md` を以下の固定構造で保存する（concept-research が機械的に読む）：

```markdown
# genre_sentei.md
対象者: ／作成日: ／パターン: ①売りたいもの未定 or ②明確（売りたいもの: ）

## 確定ジャンル
（ジャンル名＋特化テーマの方向性＋本人が選んだ理由）

## 判定の数値根拠
（トップ層の人数と数・伸びたてアカの数と数字・判定表）

## 発見済みアカウントリスト
（トップ層／伸びたて。URL・フォロワー数・投稿数。concept-research の STEP 2A の出発点にする）

## 収益化導線
（先駆者の収益化方法＋ずらし導線案＋売りたいものへの橋）

## 準備期間プラン
（不要 or 期限と内容）

## 見送った候補と理由
（次回ジャンル変更時の資産として残す）
```

4. チャットには要点だけ伝え、「このジャンルの中でどの企画・どのお手本パターンでいくかを固めるなら `concept-research`（コンセプトリサーチ）に進めます」と案内する

## 絶対に守るルール

- **抽象的な判定をしない。** 「伸びてそう」ではなく「トップ層10万人超が◯個」「50投稿未満で◯人のアカが◯個」と数値で言う。基準は references/research-criteria.md にある
- **有名人・個人のファンで伸びているアカウントをカウントしない。** 必ずプロフィールに飛んで情報発信メインか確認する
- **1年以上前に伸びたアカウントを根拠にしない**（「インスタの世界では化石」）
- **最終決定は本人。** AIは数字と選択肢を並べるところまで
- **フォロワー0で始められない方向は候補にしない**
- Instagram巡回では収集の罠に注意（ログイン状態の確認・リール一覧の遅延読み込み・再生数表記の単位・ポップアップ）。**壊れた取得結果から結論を出さない。** 空・矛盾したデータは取得側の問題を疑い、別ソースで裏取りする
- 励ましのトーンを要所で使う：「失敗は存在しない、すべて資産になる」「完璧を求めて動けないより、まず始めて修正する方が100倍速い」

## 言葉遣いのルール（insta-concept-design / concept-research と共通）

- **専門用語を出力に使わない。** ベンチマーク→「お手本アカウント」、ニッチ→「すき間」、マネタイズ→「収益化」など必ず日本語に言い換える
- **硬い敬語を使わない。**「させていただきます」ではなく「していきますね」。オトラボの講師が受講生に話すフレンドリーなトーン
- **数字を徹底的に集める。** フォロワー数・投稿数・再生数・アカウント数が報告書の説得力を決める
- **1問ずつ聞く。** 複数の質問を一度に投げない
