# スマホ巡回の宿題（STEP 2B用）

## なぜスマホでやってもらうのか（スキルが理解しておく背景）

- 「直近伸びているアカウント探し」は、発見タブをそのジャンル色に育てる（約15分そのジャンルにだけ滞在するとAIが学習する）方法が最も精度が高い。**これはスマホのインスタアプリでしかできない**
- PCブラウザのインスタはおすすめの精度が悪い（運営者の実感・スキル設計の前提）。Chrome側は検索ベースのトップ層調査（2A）に限定する
- 本人が「手が止まった」体験そのものが貴重なデータ。AIの選定だけで確定しない

## 宿題の渡し方

1. 汎用手順はNotionの「スマホ巡回ガイド」ページにまとめてある。**このリンクを必ず一緒に渡す**：
   - https://app.notion.com/p/3ac65eae373d8137bc59f449ce9f6e2d
2. その人専用の内容（検索ワード・候補ジャンル・目標数）は下のテンプレを具体化してチャットで渡す
3. 渡したら**控えを `02_巡回宿題.md` に保存し、genre_state.md を「2B提出待ち」にしてスキルを終了する**

## 提出を受けたときの処理（2C再開手順）

1. `genre_state.md` を読んで文脈を復元する
2. 提出されたリンクを1つずつChromeで開き、以下を記録：アカウント名／URL／フォロワー数／投稿数／ジャンル／本人の一言コメント
3. スクショ提出の場合：画像からアカウント名を読み取り、Chromeでそのアカウントを検索して実物を確認する（**スクショだけで数字を断定しない**）
4. 提出物のうち対象外を除外する（有名人のついで投稿／1年以上前に伸びたアカ／全投稿が同じくらい再生されている個人ファン型）。除外したときは理由を優しく説明する（「見つけてくれたこと自体がナイス」のトーン）
5. 2Aのトップ層調査と統合し、`research-criteria.md` の判定表でジャンルごとにGo/No-Go判定 → 提示 → 本人に選んでもらう
6. 提出が目標数未満だったら：あるものでまず判定する（追加提出はいつでも歓迎と伝える）。「見つからなかった」も重要データ——そのジャンルは「直近の伸び」が弱い可能性として判定表に反映する。ただし断定前に、検索ワードを変えた短い追加宿題か、特化テーマの投稿単体バズの確認（条件付きGoルート）を検討する
