# concept-research｜コンセプトリサーチ

## このスキルについて

コンセプトは頭で考えるものではなく、**リサーチで裏取りしながら決める**もの。このスキルは4スキル連携の3番目を担う：

```
insta-concept-design Phase1-2（自己分析・ジャンル候補10） → genre-sentei（ジャンル確定） → concept-research（本スキル・企画を市場で裏取り） → concept-brush-up（決定版） → insta-concept-design Phase3（アカウント名・プロフ）
```

流れは7ステップ。STEP 2の途中で**ユーザーのスマホ巡回待ちのため一旦停止する**のが正常な動作（重要工程なので止まってよい）。

| STEP | 内容 | 詳細指示書 |
|---|---|---|
| 0 | 引き継ぎ＋ヒアリング | 本ファイル |
| 1 | ターゲット深掘り＋検索ワード確定（**深掘りはここだけ**） | 本ファイル |
| 2 | 企画リサーチ（2A: Chrome検索巡回／2B: スマホ巡回宿題→**停止**／2C: 統合・強度判定） | `references/research-criteria.md` |
| 3 | ベンチマークのパターンカード分析 | `references/analysis-guide.md` |
| 4 | 見せ方・世界観ベンチマーク | `references/analysis-guide.md` |
| 5 | 自分の独自性の素材出し | `references/analysis-guide.md` |
| 6 | HTML報告書＋04_リサーチ.md 出力 | 本ファイル＋`assets/report_template.html` |

**該当STEPを始める前に必ず対応する指示書を読むこと。** 判定基準・分析手順はすべて指示書に数値と具体手順で書いてある。感覚で判定しない。

## 中断・再開の仕組み（最初に理解しておくこと）

- 進行状態は `00_state.md` に書く（このスキル専用の research_state.md は廃止。2026-09-03）。STEPが進むたびに更新する
- スキル起動時は**まず `00_state.md` を読む**。「2B提出待ち」で止まっていたら 2C から再開する（「リサーチの続き」「提出するね」はほぼ再開）
- ユーザーがリンクやスクショを貼ってきたら、それは2Bの提出物。2Cから再開する
  - ※genre-sentei にも同じ提出制の宿題がある。**どちらの宿題待ちかは `00_state.md` の「待ち状態」に書いてある**ので、そこで判定する

## 出力フォルダ（4スキル共通・1人1フォルダ）

**対象者ごとにフォルダは1つだけ。フォルダ名に日付を付けない。**

```
~/Documents/Claude/Projects/インスタコンセプト設計/<対象者名>/
├── 00_state.md                 ← 進行状態＋成果物の索引（全スキル共通の正本）
├── 01_自己分析レポート.md
├── 02_ジャンル候補10.md / .html
├── 03_ジャンル選定.md / 03_ジャンル選定報告書.html   ← genre-sentei（このスキルの入力）
├── 04_リサーチ.md / 04_リサーチ報告書.html / shots/  ← ★このスキルの出力
├── 05_コンセプト10案.html
├── 06_決定版コンセプト.md
├── 07_アカウント名_プロフィール.md
└── 宿題_スマホ巡回.md            ← 巡回の宿題を出したときの控え
```

**起動時に必ず最初にやること**

1. `<対象者名>/00_state.md` を探して読む。あれば現在地・待ち状態・確定事項がすべて分かる（他のファイルを総なめしない）
2. 無ければ**旧形式のフォルダ**を探す（`<対象者名>_<日付>` `<対象者名>_リサーチ_<日付>` `<対象者名>_ジャンル選定_<日付>`）。見つかったら中身を読んで作業は続行し、**1つのフォルダに寄せてよいかユーザーに確認してから**移す。確認なしに移動・削除しない
3. それも無ければ新規作成する

**終了時に必ずやること**：`00_state.md` を更新する。
待ち状態には**どのスキルの宿題を待っているか**を必ず書く（genre-sentei にも同じ提出制の宿題があるため）。

## STEP 0：引き継ぎ＋ヒアリング

1. `00_state.md` を読んでから、次の順に読む：
   - **`03_ジャンル選定.md`（genre-sentei の成果物）が最重要。** 確定ジャンル・特化テーマを前提にし、「発見済みアカウントリスト」をSTEP 2Aの出発点にする（同じアカウントを探し直さない）。収益化導線・準備期間プランも引き継ぐ
   - `01_自己分析レポート.md`（独自性素材シートがあれば最重要）
   - `02_ジャンル候補10.md`（本人が選んだ候補と、「これは無理」と言ったもの。**蒸し返さない**）
2. **ジャンルが確定していない場合**（`03_ジャンル選定.md` が無い）：先に genre-sentei（ジャンル選定）を案内する。企画リサーチはジャンルが1つに決まってからが効率的
3. 引き継ぎファイルが何も無い場合：Webアプリの書き出しファイル `~/Downloads/インスタアカウント設計書*.md`（複数あれば最新）を探し、あれば `<対象者名>/01_自己分析レポート.md` として保存して使う。それも無ければ「これまでの結果をコピペしてもらえますか？」と案内
4. 初期設計なしでも動ける。その場合＋不足がある場合のみヒアリング（**1問ずつ**）：
   - 発信したいジャンル・売りたいもの（ゴール）
   - 過去の自分・今の自分の悩み（生の言葉で）
   - 生い立ち・これまでの経験（どこで育ち、どんな仕事や暮らしを経て今に来たか）。**01に「2-1. 生い立ち・これまでの経験」の見出しが無いとき（Webアプリ版・旧版の01／01が無いとき）は、初期設計があってもここで1回だけ聞く。**見出しがあれば聞かない。「本人の希望で未記入」とあれば聞かない。聞く前に「話せる範囲で大丈夫です。話したくない所は飛ばしてください」と必ず伝える。飛ばした所は聞き直さない。聞き方の例は insta-concept-design の `references/phase1_self_analysis.md`「生い立ち・経験の聞き方」
   - 自分の特徴リスト（「良いことじゃなくてOK、ネガティブなことほど武器になります」と必ず伝える）
   - 顔出しできるか・どこまで出せるか（顔NG／後ろ姿／手元だけ等）
   - 撮影環境（家で撮れるか・外だけか）

## STEP 1：ターゲット深掘り＋検索ワード確定

**「誰の・どんな悩みを」の深掘りはこのスキルだけでやる。**（2026-09-03：以前は insta-concept-design の Phase 2 にも同じ工程があり二重だったので、そちらから外してここに一本化した。ジャンルが決まってからの方が精度が出る）

対話で進める（自動化しない）。詳しい深掘り例は `references/research-criteria.md` の冒頭にある。

1. **「なぜそこに悩むのか」を掘る。** 表面の悩みで止めない。「痩せたい人」→なぜ？→「旦那にもう一度惚れさせたい」→「産後太りに悩む30代主婦」のように、感情の根っこ→実在する1人まで落とす
2. ターゲットは**過去の自分か親しい友達**をベースにする（架空の人物を想像させない。心理を一番理解できる実在の人が最強）
3. 検定3つ（全部クリアするまで確定しない）：
   - ❌「そんな人いるの？」— 実在するイメージが湧かない設定
   - ❌「それ全員じゃん」— 絞れていない設定
   - ❌ フォロワー0で成立しない — 依頼者・フォロワー参加が前提の方向はNG
4. 確定したターゲット定義から**検索ワードを5〜10個**作る（ジャンル名×悩みワードの掛け合わせ。例:「写真の撮り方」「自撮り 盛れる」「彼氏 撮ってもらう」）。これがSTEP 2A/2B共通の武器になる
5. `00_state.md` の「確定したこと」にターゲット定義を追記する

## STEP 2：企画リサーチ（心臓部）

**開始前に必ず `references/research-criteria.md` を読む。** 手順・数値基準・落とし穴チェックの全てがそこにある。

- **2A（Chrome検索巡回）**: Claude in ChromeでInstagram・TikTok・YouTubeを**検索ベース**で巡回する。PCのおすすめ欄・発見欄は精度が悪いので**使わない**（検索結果と、そこから飛んだアカウントのプロフィールだけを見る）。Xログインがあればまとめバズも見る
- **2B（スマホ巡回の宿題）**: `references/smartphone-homework.md` の指示書テンプレをユーザー向けに具体化して渡し、**スキルはここで一旦停止**。「スマホのおすすめ欄の方がPCより精度が高いので、ここはあなたのスマホが最強のリサーチツールです」と価値を伝える。指示書の控えを `宿題_スマホ巡回.md` に保存、`00_state.md` の待ち状態を「concept-research の 2B 提出待ち」にして終了
- **2C（統合・強度判定）**: 提出が来たら再開。2A＋2Bの候補を統合し、数値基準でスコアリング→候補3〜5方向に絞って根拠つきで提示→「**自分が興味を持てて、続けられそうな方向はどれですか？**」と本人に選んでもらう（対話）→選んだ方向はコメント欄で視聴者層を裏取り

## STEP 3：ベンチマークのパターンカード分析

**開始前に必ず `references/analysis-guide.md` を読む。**

提出された＋2Aで見つけたベンチマークアカウントを1つずつ分解する。カード1枚＝1アカウント：冒頭・世界観のスクリーンショット（`shots/` に保存）＋コンセプトの言語化（誰が×誰に×どのように）＋**6項目の分解**（①誰が＝属性 ②誰が＝生い立ち・経験 ③どんなことを ④どのように ⑤何が解決できるか ⑥どんな未来へ＝期限と期限の理由の有無まで）＋4要素の突出診断＋**強みの掛け算式の逆算**＋自分に応用するなら。

6項目は講座STEP5の「競合は6つで分析する」と同じ並び。受講生はこのあと同じ6項目で自分のコンセプトを書くので、項目名を変えない。②⑥は本人が公開している範囲と投稿から読み取れる範囲だけ書き、推測で作らない（読み方は `references/analysis-guide.md`「6項目の読み方」）。

ゴールは、ユーザーがカードを見比べて「**じゃあ自分はこのパターンでいこう**」と判断できる状態。

## STEP 4：見せ方・世界観ベンチマーク

`references/analysis-guide.md` の後半に従い、カード群から①編集テイストの参考1人 ②映し方ロールモデル（顔出しなし5パターン対応）③アフレコの目星 ④世界観3要素の方針、を選定・提案する。

## STEP 5：自分の独自性の素材出し

`references/analysis-guide.md` の手順で対話する。初期設計の独自性素材シートがあれば出発点にする（ゼロから再ヒアリングしない）。特徴の数値化掛け算→ギャップ探索→エピソード掘り起こし。STEP 3で逆算した成功者の掛け算式と自分の式を**並べて見せる**。

最後に、本人が選んだお手本3人と自分を**6項目で並べた表**を作る（同じ欄＝需要の証拠／違う欄＝自分の立ち位置／6つとも同じ＝劣化版）。自分の列が、concept-brush-up で書く6行のコンセプトの下書きになる。

## STEP 6：成果物の出力

1. `assets/report_template.html` をベースにHTML報告書を生成（デザイン・配色はテンプレートのまま変えない）。構成：企画候補ランキング／パターンカード集（スクショ埋め込み・6項目の表つき）／お手本3人と自分の6項目の並べ表／ターゲット定義／4要素突出診断／独自性素材／次の一歩
   - スクリーンショットは `shots/` からの相対パス参照でよい（報告書とshotsは同フォルダ内なのでChromeで開ける）
2. `<対象者名>/04_リサーチ報告書.html` に保存し、`open <ファイルパス>` でブラウザで開いて見せる（Chrome拡張のnavigateは file:// URLに非対応＝httpsを前置してしまうので使わない。2026-07-29実機確認）
3. `<対象者名>/04_リサーチ.md` を以下の固定構造で保存する（concept-brush-up が機械的に読む。旧名 concept_research.md は2026-09-03に改名）：

## 絶対に守るルール

- **抽象的な判定をしない。** 「伸びてそう」ではなく「平均の◯倍」「類似企画が上位に◯件」と数値で言う。基準は references/research-criteria.md にある
- **個人の影響力バズを企画として採用しない。** 必ずプロフィールに飛んで相対倍率を確認する
- **参考アカウントの最終選定はユーザー自身の提出物を優先する。** AIの選定だけで確定しない（スマホ巡回提出が主・Chrome巡回は補助）
- Instagram巡回では bunseki-competitor-account で記録済みの収集の罠に注意（ログイン状態の確認・リール一覧の遅延読み込み・再生数表記の単位・ポップアップ）。壊れた取得結果から結論を出さない。空・矛盾したデータは取得側の問題を疑い、別ソースで裏取りする

## 言葉遣いのルール（insta-concept-design と共通）

- **専門用語を出力に使わない。** ベンチマーク→「お手本アカウント」、ペルソナ→「届けたい相手」、エンゲージメント→「反応」など必ず日本語に言い換える
- **硬い敬語を使わない。**「させていただきます」ではなく「していきますね」。オトラボの講師が受講生に話すフレンドリーなトーン
- **数字を徹底的に集める。** 再生数・フォロワー数・倍率・何人に1人、が報告書の説得力を決める
- **1問ずつ聞く。** 複数の質問を一度に投げない

## 出す前の書き癖チェック

成果物の文章を出す前に、下の問いで自分の文を見直してから渡す。手順の中身は変えない。特別なファイルやプログラムは要らない（Mac・Windowsどちらでも同じようにやる）。

- **見直す文**：渡すHTMLレポートの文章
- **見直さない物**：表の数字・コード・ファイル名、文字起こし、参考投稿の引用、ユーザーが書いた原文。これらは書き換えずにそのまま残す（ただし表の数字と本文の数字が食い違っていないかは、問い5で見る）。題名・回の名前・商品名のように、目次や他の回・サイトとつながっている名前も勝手に変えず、直したいときはユーザーに聞く
- **いつ**：成果物を出す前に、全体を1周＋直した所の確かめ。途中の返事・確認の質問・作業の報告には当てない
- **スキルの決まりが先**：このスキルが決めている口調（話し言葉・方言・コーチの口調など）・改行・文字数・見出しの形・絵文字、そして台本や文面の型（締めの決まり文句・余韻や「つづく」の締め・わざと繰り返す言葉・気持ちをそのまま言う独白・問いかけ・必ず残すと決めた注記や欄）は、下の問いより先に守る。問いで見るのは、意味が伝わるか・事実が正しいかだけ

### 見直しの問い（20）

問いには2種類ある。**［全部］**は台本・ストーリーズ・報告書のどれにも当てる。**［説明］**は報告書・設計書・指摘文・改善案のような、何かを説明する文だけに当てる（台本・ストーリーズの文面には当てない）。

**名前と番号**
1. ［全部］最初に付けた呼び名を、最後まで同じ名前で使っているか。1つの言葉で2つの別の物を指していないか
2. ［全部］①②…や「1つ目・2つ目」の番号が、別々の物にかぶっていないか。番号は出てくる順に1から振ってあるか
3. ［全部］初めて読む人が何のことか分からない言葉が、説明なしで出ていないか。「さっきの例」「前の回で話した」のように、前の話を覚えている前提で書いていないか。「書き出した10個」「決めた場所」のように、この文章の中で作っていない物を、もうある物として指していないか。見出し・図の札・矢印の横の短い一言も含めて上から読み、札の「これ」「それ」は札が置かれた位置から読んで何を指すか分かるかで確かめる。人を記号で呼ばず、中身で呼んでいるか（例：「夜しか撮影できない会社員」）

**事実と数字**
4. ［全部］数字・出来事・セリフは、ユーザーの発言、渡された材料、このスキルが作ったファイルのどれかにあるか。どこにも無い物は書かない。どうしても要る時は〔要確認〕を付けてユーザーに聞く。文字数・枚数・秒数のように数えられる物は、書く前に実際に数える（「〜なら大丈夫」とぼかさない）
5. ［全部］同じ物の数字・期間・回数が、場所によって違っていないか（例：「3ヶ月」と「半年」）。数字だけでなく、前の段落や別の欄で言い切ったことと、あとの文が食い違っていないか（例：「やらなくていい」と言ったあとで、それをやった例を出す）。「〜しなくてよい」「〜だけでいい」と言い切った所は、後ろの段にそれを打ち消す例が出てこないかを最後まで追う
6. ［全部］「誰も」「必ず」「絶対」「〜しかない」と言い切った文に、当てはまらない例を1つでも思いつけるなら、条件を付けて言い直す。台本・文面の話し言葉でも、体・肌・お金・効き目について「〜する」「〜しない」「〜が残る」と言い切った所は同じ。言い換えのついでに、元に無かった言い切りを足さない
7. ［全部］その仕事やジャンルの経験者（美容師・飲食店の人・子育て中の親など）が読んで、直したくなる所はないか。道具やアプリの使い方、手間や値段の比べ方、届くまでの日数などが、現実のやり方と合っているか。よく知らない道具や仕組みは名前を書かず、ユーザーに聞く
8. ［説明］数字を出したら、それが読む人にとってどういうことか（多いのか少ないのか、何と比べてか、だから何をするのか）を同じ所で言っているか。数字だけを置いて先へ進んでいないか

**理由とつながり**
9. ［説明］言い切った文のそばに、そう言える理由があるか。「AだからB」「Aと言い直すとBになる」のAからBへの一歩を、読む人が自分で踏めるか（自分で別の例を1つ作り、同じ言い直しができるか試す。できないなら、間の一歩を文で足す）。「ので」の前が、結論を言い換えただけになっていないか。すぐ後ろで別の仕組みを説明しているなら、そちらが本当の理由なので、理由の文をそちらに合わせる。1つの結論に理由が2つ以上あるなら食い違っていないか。見出しと本文で、原因の説明が別々になっていないか
10. ［説明］ひとまとまり（1つの段落・1つの欄）で言いたいことは1つか。2文目・3文目は、1文目を読んだ人が次に聞きたくなること（理由・その先どうなるか）に答えて話を進めているか。事実を1行ずつ並べて終わり、行と行の関係を読む人任せにしていないか
11. ［全部］見出しと本文で、言っていることが同じか。比べる2つが同じ物差しで並んでいるか（片方は2つの組み合わせ、もう片方は3つ、になっていないか）。主語と述語がかみ合っているか（「見せ方が埋まる」のように、何が何をしたのか読めない文になっていないか）。言葉が途中で抜けて、意味が取れなくなった文はないか（短い札や実況の言い切りは問題にしない）

**話し方**
12. ［全部］1本の中で、話し方が途中で入れ替わっていないか（です・ます と だ・である、標準語と方言、話し言葉と書き言葉）。告知の枚・お願い・DMの締めだけ、急にかしこまった言い方やお店の決まり文句に変わっていないか。スキルが話し方を決めているなら、始めから終わりまでそれで通す。ただし揃えるのはスキルが決めた範囲だけ。お礼・お詫び・独白・締めの一言で、わざと違う言い方をしている所まで平らにしない
13. ［全部］ひねった言い方や作る側だけが分かる言葉（「角度」「解像度」「横断して」など）を、まっすぐな言い方にしたか（例：「この人に向けて作ります」）。人や物ではなく、雰囲気の言葉（「この景色」「あの日の自分」「ブランドの想い」など）が文の頭に立って、詩のようにまとめた文はないか（その場で目に見える物・人の動きで書く）。たとえ話を出したら、すぐあとで本当の言葉（実際の画面・物・数字）に言い直し、そのあとの段落や枚までたとえを使い続けていないか。本文に「下書き」「確認用」のような作業のメモが入っていないか
14. ［全部］読む人にお願いする文（登録して・保存して・待機して・コメントして）に、なぜ今それをやるのか（やらないと何が困るか、やると何が楽か）が、その文か近くに添えてあるか
15. ［全部］参考や見本から借りたのは組み立て（順番・長さ・間の取り方）だけか。スキルが「残す」と決めた型の外で、参考の言い回しをそのまま、または語尾だけ変えて使っていないか。その文の中身を、この人が話したどの一言・渡されたどの材料から取ったか言えるかで確かめる

**読む人への向き方**
16. ［説明］「このあと説明します」「ここからが大事です」のように、次の話を予告するだけの文はないか。その文を抜いて読み直しても話が通じるなら消す。同じことを言い直しているだけの所は、1つにまとめる
17. ［説明］読む人の頭の中を言い当てる文（「〜と思っていませんか」「〜で止まりがちです」）や、持ち上げるだけの文（「さすがの着眼点です」）はないか。言いたい中身があるなら、何ができているかを実際の数字や画面の言葉で書く
18. ［説明］改善案や「こうするといい」の文は、画面に何が映るか・誰が何をするかまで書いてあるか。「いい雰囲気に」「前向きに」「伝わるように」で止まっていないか

**並べたときと締め**
19. ［全部］何本・何枚も並ぶ物（ストーリーズの各枚、台本や案の一覧、各回・各章の書き出し）を続けて読んで、書き出しや締めが同じ言葉・同じ形のくり返しになっていないか。同じお願い・同じ決まり文句の締めが続くなら、何枚かは中身（新しい事実・次にやること）で終える
20. ［説明］最後の段落に、読んだ人が次にやること（どこを開いて何をするか）が書いてあるか。「頑張りましょう」「きっと伝わるはず」だけで終わっていないか

### 当てはまった文の直し方

- 直す前に、その文がスキルの決まりで「そのまま」とした欄・締め・独白・ほめ言葉に入っていないかを先に見る。入っていれば、事実の誤り以外は触らない
- 直す前に、その行・その枚が何のためにあるか（怖がらせる・買ってもらう・次を待ってもらう・ほめる）を1行で言う。消すのは間違いだけ。直したあとの文が、元の文の役目（ほめる・背中を押す・怖さや期待の山を作る・言い切って決めさせる）をまだ果たしているかを確かめる。言い切りを「〜しやすい」「〜かもしれません」に弱めて済ませない
- その文は捨てて、伝えたいことを1行で言い直してから新しく書く。似た言葉に入れ替えるだけ・後ろに言葉を足すだけで済ませない（文の「誰が・何を・どうする」を1行で言えないときも同じ）。伝えたい中身が無い文は消す
- 図の札・短い一言は、指す物を取り違えるときと事実が違うときだけ直す。別の段の話や、書かなくても分かる前提を札に足さない。気分を上げる一言を、すぐ上と同じ説明に置き換えない
- 名前・番号・数字のずれは、最初に決めた1つに**全文で**揃える（1か所だけ直すと、別の場所とまたずれる）
- 材料が足りなくて正しく書けない事実は、作らずにユーザーに聞く。確かめが取れない行も、消したり空欄にしたりせず、残したまま〔要確認〕を付ける（手本の行・冒頭の引きのように役目のある行は特に）
- 直した文とその前後だけ、もう一度問いを当てる。直したことで新しいずれが出ていないかを見る。もう一度直し直すときは、前に直した所の一覧と照らし、理由なく元に戻った所が無いかを確かめる

### 出すとき

成果物を出し終えたあと、返事のいちばん最後に1行空けて、次の1行を添える。報告書・台本・文面の中には書かない。

`書き方の見直し：◯か所直しました（名前のずれ・数字の食い違い・意味の取れない文など）`

直す所が無かった時は `書き方の見直し：直す所はありませんでした`。
