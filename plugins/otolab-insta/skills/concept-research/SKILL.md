# concept-research｜コンセプトリサーチ

## このスキルについて

コンセプトは頭で考えるものではなく、**リサーチで裏取りしながら決める**もの。このスキルは4スキル連携の3番目を担う：

```
insta-concept-design Phase1-2（自己分析・ジャンル候補10） → genre-sentei（ジャンル確定） → concept-research（本スキル・企画を市場で裏取り） → concept-brush-up（決定版） → insta-concept-design Phase3（アカウント名・プロフ）
```

流れは7ステップ。STEP 2の途中で**ユーザーのスマホ巡回待ちのため一旦停止する**のが正常な動作（重要工程なので止まってよい）。

| STEP | 内容 | 詳細指示書 |
|---|---|---|
| 0 | 引き継ぎ＋ヒアリング | 本ファイル |
| 1 | ターゲット深掘り＋検索ワード確定（**深掘りはここだけ**） | 本ファイル |
| 2 | 企画リサーチ（2A: Chrome検索巡回／2B: スマホ巡回宿題→**停止**／2C: 統合・強度判定） | `references/research-criteria.md` |
| 3 | ベンチマークのパターンカード分析 | `references/analysis-guide.md` |
| 4 | 見せ方・世界観ベンチマーク | `references/analysis-guide.md` |
| 5 | 自分の独自性の素材出し | `references/analysis-guide.md` |
| 6 | HTML報告書＋04_リサーチ.md 出力 | 本ファイル＋`assets/report_template.html` |

**該当STEPを始める前に必ず対応する指示書を読むこと。** 判定基準・分析手順はすべて指示書に数値と具体手順で書いてある。感覚で判定しない。

## 中断・再開の仕組み（最初に理解しておくこと）

- 進行状態は `00_state.md` に書く（このスキル専用の research_state.md は廃止。2026-09-03）。STEPが進むたびに更新する
- スキル起動時は**まず `00_state.md` を読む**。「2B提出待ち」で止まっていたら 2C から再開する（「リサーチの続き」「提出するね」はほぼ再開）
- ユーザーがリンクやスクショを貼ってきたら、それは2Bの提出物。2Cから再開する
  - ※genre-sentei にも同じ提出制の宿題がある。**どちらの宿題待ちかは `00_state.md` の「待ち状態」に書いてある**ので、そこで判定する

## 出力フォルダ（4スキル共通・1人1フォルダ）

**対象者ごとにフォルダは1つだけ。フォルダ名に日付を付けない。**

```
~/Documents/Claude/Projects/インスタコンセプト設計/<対象者名>/
├── 00_state.md                 ← 進行状態＋成果物の索引（全スキル共通の正本）
├── 01_自己分析レポート.md
├── 02_ジャンル候補10.md / .html
├── 03_ジャンル選定.md / 03_ジャンル選定報告書.html   ← genre-sentei（このスキルの入力）
├── 04_リサーチ.md / 04_リサーチ報告書.html / shots/  ← ★このスキルの出力
├── 05_コンセプト10案.html
├── 06_決定版コンセプト.md
├── 07_アカウント名_プロフィール.md
└── 宿題_スマホ巡回.md            ← 巡回の宿題を出したときの控え
```

**起動時に必ず最初にやること**

1. `<対象者名>/00_state.md` を探して読む。あれば現在地・待ち状態・確定事項がすべて分かる（他のファイルを総なめしない）
2. 無ければ**旧形式のフォルダ**を探す（`<対象者名>_<日付>` `<対象者名>_リサーチ_<日付>` `<対象者名>_ジャンル選定_<日付>`）。見つかったら中身を読んで作業は続行し、**1つのフォルダに寄せてよいかユーザーに確認してから**移す。確認なしに移動・削除しない
3. それも無ければ新規作成する

**終了時に必ずやること**：`00_state.md` を更新する。
待ち状態には**どのスキルの宿題を待っているか**を必ず書く（genre-sentei にも同じ提出制の宿題があるため）。

## STEP 0：引き継ぎ＋ヒアリング

1. `00_state.md` を読んでから、次の順に読む：
   - **`03_ジャンル選定.md`（genre-sentei の成果物）が最重要。** 確定ジャンル・特化テーマを前提にし、「発見済みアカウントリスト」をSTEP 2Aの出発点にする（同じアカウントを探し直さない）。収益化導線・準備期間プランも引き継ぐ
   - `01_自己分析レポート.md`（独自性素材シートがあれば最重要）
   - `02_ジャンル候補10.md`（本人が選んだ候補と、「これは無理」と言ったもの。**蒸し返さない**）
2. **ジャンルが確定していない場合**（`03_ジャンル選定.md` が無い）：先に genre-sentei（ジャンル選定）を案内する。企画リサーチはジャンルが1つに決まってからが効率的
3. 引き継ぎファイルが何も無い場合：Webアプリの書き出しファイル `~/Downloads/インスタアカウント設計書*.md`（複数あれば最新）を探し、あれば `<対象者名>/01_自己分析レポート.md` として保存して使う。それも無ければ「これまでの結果をコピペしてもらえますか？」と案内
4. 初期設計なしでも動ける。その場合＋不足がある場合のみヒアリング（**1問ずつ**）：
   - 発信したいジャンル・売りたいもの（ゴール）
   - 過去の自分・今の自分の悩み（生の言葉で）
   - 自分の特徴リスト（「良いことじゃなくてOK、ネガティブなことほど武器になります」と必ず伝える）
   - 顔出しできるか・どこまで出せるか（顔NG／後ろ姿／手元だけ等）
   - 撮影環境（家で撮れるか・外だけか）

## STEP 1：ターゲット深掘り＋検索ワード確定

**「誰の・どんな悩みを」の深掘りはこのスキルだけでやる。**（2026-09-03：以前は insta-concept-design の Phase 2 にも同じ工程があり二重だったので、そちらから外してここに一本化した。ジャンルが決まってからの方が精度が出る）

対話で進める（自動化しない）。詳しい深掘り例は `references/research-criteria.md` の冒頭にある。

1. **「なぜそこに悩むのか」を掘る。** 表面の悩みで止めない。「痩せたい人」→なぜ？→「旦那にもう一度惚れさせたい」→「産後太りに悩む30代主婦」のように、感情の根っこ→実在する1人まで落とす
2. ターゲットは**過去の自分か親しい友達**をベースにする（架空の人物を想像させない。心理を一番理解できる実在の人が最強）
3. 検定3つ（全部クリアするまで確定しない）：
   - ❌「そんな人いるの？」— 実在するイメージが湧かない設定
   - ❌「それ全員じゃん」— 絞れていない設定
   - ❌ フォロワー0で成立しない — 依頼者・フォロワー参加が前提の方向はNG
4. 確定したターゲット定義から**検索ワードを5〜10個**作る（ジャンル名×悩みワードの掛け合わせ。例:「写真の撮り方」「自撮り 盛れる」「彼氏 撮ってもらう」）。これがSTEP 2A/2B共通の武器になる
5. `00_state.md` の「確定したこと」にターゲット定義を追記する

## STEP 2：企画リサーチ（心臓部）

**開始前に必ず `references/research-criteria.md` を読む。** 手順・数値基準・落とし穴チェックの全てがそこにある。

- **2A（Chrome検索巡回）**: Claude in ChromeでInstagram・TikTok・YouTubeを**検索ベース**で巡回する。PCのおすすめ欄・発見欄は精度が悪いので**使わない**（検索結果と、そこから飛んだアカウントのプロフィールだけを見る）。Xログインがあればまとめバズも見る
- **2B（スマホ巡回の宿題）**: `references/smartphone-homework.md` の指示書テンプレをユーザー向けに具体化して渡し、**スキルはここで一旦停止**。「スマホのおすすめ欄の方がPCより精度が高いので、ここはあなたのスマホが最強のリサーチツールです」と価値を伝える。指示書の控えを `宿題_スマホ巡回.md` に保存、`00_state.md` の待ち状態を「concept-research の 2B 提出待ち」にして終了
- **2C（統合・強度判定）**: 提出が来たら再開。2A＋2Bの候補を統合し、数値基準でスコアリング→候補3〜5方向に絞って根拠つきで提示→「**自分が興味を持てて、続けられそうな方向はどれですか？**」と本人に選んでもらう（対話）→選んだ方向はコメント欄で視聴者層を裏取り

## STEP 3：ベンチマークのパターンカード分析

**開始前に必ず `references/analysis-guide.md` を読む。**

提出された＋2Aで見つけたベンチマークアカウントを1つずつ分解する。カード1枚＝1アカウント：冒頭・世界観のスクリーンショット（`shots/` に保存）＋コンセプトの言語化＋4要素の突出診断＋**強みの掛け算式の逆算**＋自分に応用するなら。

ゴールは、ユーザーがカードを見比べて「**じゃあ自分はこのパターンでいこう**」と判断できる状態。

## STEP 4：見せ方・世界観ベンチマーク

`references/analysis-guide.md` の後半に従い、カード群から①編集テイストの参考1人 ②映し方ロールモデル（顔出しなし5パターン対応）③アフレコの目星 ④世界観3要素の方針、を選定・提案する。

## STEP 5：自分の独自性の素材出し

`references/analysis-guide.md` の手順で対話する。初期設計の独自性素材シートがあれば出発点にする（ゼロから再ヒアリングしない）。特徴の数値化掛け算→ギャップ探索→エピソード掘り起こし。STEP 3で逆算した成功者の掛け算式と自分の式を**並べて見せる**。

## STEP 6：成果物の出力

1. `assets/report_template.html` をベースにHTML報告書を生成（デザイン・配色はテンプレートのまま変えない）。構成：企画候補ランキング／パターンカード集（スクショ埋め込み）／ターゲット定義／4要素突出診断／独自性素材／次の一歩
   - スクリーンショットは `shots/` からの相対パス参照でよい（報告書とshotsは同フォルダ内なのでChromeで開ける）
2. `<対象者名>/04_リサーチ報告書.html` に保存し、`open <ファイルパス>` でブラウザで開いて見せる（Chrome拡張のnavigateは file:// URLに非対応＝httpsを前置してしまうので使わない。2026-07-29実機確認）
3. `<対象者名>/04_リサーチ.md` を以下の固定構造で保存する（concept-brush-up が機械的に読む。旧名 concept_research.md は2026-09-03に改名）：

```markdown
# 04_リサーチ.md
対象者: ／作成日: ／リサーチフォルダ: 

## ターゲット定義
（実在する1人の描写・悩みの根っこ・深掘りの過程）

## 企画候補トップ3
（各: 企画名／強度スコアと数値根拠／ベンチマークURL／落とし穴チェック結果）

## 本人が選んだ方向
（2Cでの選択と理由）

## 採用パターン
（パターンカードのどれをベースにするか＋そのアカウントの掛け算式）

## 編集・見せ方方針
（編集テイスト参考／映し方ロールモデル／アフレコ方針）

## 世界観方針
（身に着けるもの／映り込むもの／身だしなみ、それぞれの方向性と参考）

## 独自性素材
（自分の掛け算式／ギャップ／語れるエピソード）

## 4要素突出診断

```

4. チャットには要点だけ伝え、「この結果をもとに決定版コンセプトを作るなら `concept-brush-up`（コンセプト磨き上げ）に進めます」と案内する

## 絶対に守るルール

- **抽象的な判定をしない。** 「伸びてそう」ではなく「平均の◯倍」「類似企画が上位に◯件」と数値で言う。基準は references/research-criteria.md にある
- **個人の影響力バズを企画として採用しない。** 必ずプロフィールに飛んで相対倍率を確認する
- **参考アカウントの最終選定はユーザー自身の提出物を優先する。** AIの選定だけで確定しない（スマホ巡回提出が主・Chrome巡回は補助）
- Instagram巡回では bunseki-competitor-account で記録済みの収集の罠に注意（ログイン状態の確認・リール一覧の遅延読み込み・再生数表記の単位・ポップアップ）。壊れた取得結果から結論を出さない。空・矛盾したデータは取得側の問題を疑い、別ソースで裏取りする

## 言葉遣いのルール（insta-concept-design と共通）

- **専門用語を出力に使わない。** ベンチマーク→「お手本アカウント」、ペルソナ→「届けたい相手」、エンゲージメント→「反応」など必ず日本語に言い換える
- **硬い敬語を使わない。**「させていただきます」ではなく「していきますね」。オトラボの講師が受講生に話すフレンドリーなトーン
- **数字を徹底的に集める。** 再生数・フォロワー数・倍率・何人に1人、が報告書の説得力を決める
- **1問ずつ聞く。** 複数の質問を一度に投げない
