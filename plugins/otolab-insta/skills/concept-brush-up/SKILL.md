# concept-brush-up｜コンセプト磨き上げ

## このスキルについて

**コンセプトを1つに決めるのは、4スキル連携の中でこのスキルだけ。**

```
insta-concept-design Phase1-2（自己分析・ジャンル候補10／決めない）
   → genre-sentei（ジャンル確定） → concept-research（企画を裏取り）
   → concept-brush-up（本スキル・★決定版コンセプトを決める）
   → insta-concept-design Phase3（アカウント名・プロフィール）
```

流れは3ステップ：

1. **引き継ぎ** — 前工程の成果物を読み込む
2. **10案提案** — 差別化コンセプト10案をHTMLレポートでChromeに表示
3. **磨き上げ** — 対話でブラッシュアップして、決定版コンセプトを1つ決める

コンセプト生成の前に、必ず `references/raku-shinai-theory.md` を読むこと。理論の4ステップ・発想パターン7分類・勝ち筋の5判断材料がこのスキルのエンジン。

### Phase 2 の「ジャンル候補10」との違い（混同しない）

どちらも10枚だが、**粒度も目的も別物**。受講生に聞かれたらこう説明する。

| | insta-concept-design Phase 2 の10枚 | このスキルの10案 |
|---|---|---|
| 何を並べるか | 発信**ジャンル**の候補（枠） | ジャンル内の**差別化コンセプト**（中身） |
| 元になる情報 | 自己分析の素材だけ | 確定ジャンル＋市場リサーチの裏取り結果 |
| 決めるか | **決めない**（気になるものを2〜3個選ぶだけ） | **決める**（決定版を1つ） |
| 例 | 【作り置き・冷凍ストック】日曜3時間で平日5日を終わらせる | 「日曜3時間で5日分」を軸に、失敗した作り置きも全部出す少数派ポジション |

## Step 1：引き継ぎデータの読み込み

`00_state.md` を読んでから、次の優先順で読む：

1. **`04_リサーチ.md`（concept-research の成果物）が最重要。** 「ターゲット定義／企画候補トップ3／本人が選んだ方向／採用パターン／お手本の6項目／お手本3人と自分の6項目／独自性素材／4要素突出診断」を引き継ぎの中心に据える（6項目の見出しは2026-11-04以降の04にだけある。無ければ01から組み立てる）。リサーチ済みの人はここが一番濃い素材
2. **`03_ジャンル選定.md`（genre-sentei の成果物）**。「確定ジャンル／判定の数値根拠／収益化導線／準備期間プラン／見送った候補と理由」を読む。**10案は確定ジャンルの中で出す**（ジャンルを聞き直さない・ジャンル外の案を出さない）。収益化導線は Step 3 の「売りたいものにつながるか」と 06_決定版の「収益化への道すじ」の前提にする
3. **`01_自己分析レポート.md`**（独自性素材シート＝掛け算式・ギャップ・生い立ち・経験・エピソード・これから進みたい未来／数字の武器）。「本人の希望で未記入」に書かれた項目は聞き直さない。「発信に出してよいか」が「出さない・未確認」の経験は、10案の「誰が」にも決定版にも使わない（使いたいときは先に本人に確かめる）
4. **`02_ジャンル候補10.md`**（本人が選んだ候補と、「これは無理」と言ったもの。**蒸し返さない**）

あるものだけ読めばよい。無い場合の対応：

- Webアプリの書き出しファイル `~/Downloads/インスタアカウント設計書*.md`（複数あれば最新）を探し、あれば `<対象者名>/01_自己分析レポート.md` として保存して使う
- それも無ければ、最低限のヒアリングをする：発信ジャンル／今の立場（年齢・仕事・家族など）／生い立ち・これまでの経験（「話せる範囲で大丈夫、飛ばしてもいい」と添える。聞き方の例は insta-concept-design の `references/phase1_self_analysis.md`）／届けたい相手／自分の強み・実績（数字で）／売りたいもの・ゴール／続けられそうな作業量。**1問ずつ聞く**こと
- **リサーチ（04）もジャンル選定（03）も無いまま10案を出す場合は、その旨を必ず伝える。**「今は自己分析の情報だけで出しているので、市場の裏取りはできていません。数字で確かめるなら genre-sentei → concept-research を先に通せます」

引き継いだら「**誰が**（①属性×②生い立ち・経験を一言で）」「誰の・どんな悩みを・どう解決するか」「数字の武器」「確定ジャンル」「選んだ企画の方向・採用パターン」を2〜3行で要約してユーザーに見せ、ズレがないか確認してから次へ進む。「誰が」が空のまま10案に進まない（講座STEP5：8〜9割の人は「誰が」が抜けている）。

## Step 2：差別化コンセプト10案 → HTMLレポート

### 10案の作り方

`references/raku-shinai-theory.md` を読んだ上で、ユーザーのジャンル内で成立する「差別化コンセプト」を10案作る。

- **発想パターン7分類のうち最低5パターンに散らす**。10案が全部「継続実況」のような偏りは禁止。カードにパターン名をタグ表示する
- 各案は記事の型（コンセプト／伸びる理由／人に教えたくなる理由）＋**勝ち筋との相性**（この人の強み・数字・売りたいものとどう接続するか）の4点で書く
- **各案に「誰が」を書く。** 講座STEP5の6項目の①属性×②生い立ち・経験を、言い方を変えて一言にする（例の型：可愛いのに29年彼氏がいない→「29年間1人で強く生きてる女」）。「誰に×何を」だけで誰が書けない案は、誰でも言える発信なのでボツ。②を本人が飛ばしている人は、①属性と、本人が話した範囲の経験だけで作る
- **「どんな未来へ」（6項目の⑥）は書ける案だけ書く。** 期限と期限の理由が組める案は「期限：◯ヶ月後に◯◯／理由：◯◯までに」の形でカードに出す。理由は01の「これから進みたい未来」にある本人の言葉だけを使い、無ければ「理由：磨き上げで聞く」と書く（AIが理由を作らない）。期限が合わない案は「進みたい暮らし」だけでよい。期限は組める案だけに付け、全部の案には付けない（判定の目安は Step 3 の「どんな未来へを決める」）
- 引き継いだ**数字の武器を必ず使う**。「−36kg」「106kg時代」のような実数がキャッチコピーに入ると強い
- 「本当にやってるの？」「自分には無理だけど見たい」「友達に送りたい」のどれかを起こせない案はボツにして作り直す
- **フォロワー0人の初日でも始められる案にする。** 受講生の多くはゼロからのスタート。フォロワーの投票・コメント頼みの参加型や、お客さん・依頼者・生徒が必要な企画は、「誰に頼めばいいの？」で初日に手が止まる。ただし企画自体を捨てるのではなく、**手が届く相手に変換する**：「人の家を片付ける」→「友人の家を片付ける」のように、友人・同僚・後輩・家族で完結する形に直すと、受講生が具体的にイメージできる強い案になる。誰を巻き込むか（友人・同僚など関係性）を必ずカードに書く
- 現実的な負荷の幅をつける：全案が「毎日3時間かかる企画」だと選べない。軽め〜重めを混ぜる
- **`50-concepts-list.md` は配布禁止（他社記事の要約）。ここの案・言い回しを、受講生に見せる出力やWebアプリのプロンプトに書き写さない。** 受講生に見せてよい引き出しは `concept-examples.md` の200例だけ（2026-09-03の検証で混入事故があった）
- `references/concept-examples.md` のジャンル別200例は引き出しであって答えではない。ジャンルにそのまま近い案の流用は1〜2案まで。残りはこの人の職業・生活・性格からしか出てこない固有の案にする

### 04_リサーチ.md がある場合の追加ルール（2026-07-29）

リサーチ済みの人の10案は「机上の発想」ではなく「裏取り済みの市場」から作る：

- **企画候補トップ3・採用パターンに沿った案を10案の中心にする。** リサーチと無関係な思いつき案は多くても2〜3案まで（市場の外のワイルドカード枠として明示する）
- **各案に「掛け算式」と「ギャップ」を必ず明記する**：「特徴A(◯人に1人)×特徴B(◯人に1人)＝◯万人に1人／ギャップ：◯◯なのに◯◯」。目標は1,000万〜1億分の1（insta-concept-design と同じ基準）。カードの項目として追加する。掛け算もギャップも書けない案はボツ
- **各案に「どの要素で100点を取る案か」を付記する**（世界観／企画力／編集力／独自性のどれで突出する案か。全要素そこそこの案は伸びないのでボツ）
- **落とし穴3チェックを通す**：①テーマがバラバラにならないか ②その方向でうまくいっている実在アカウントが確認済みか・届けたい相手に矛盾がないか ③流行遅れの型をそのまま使っていないか（使うなら補強要素を明記）
- リサーチの独自性素材（本人の掛け算式・ギャップ・エピソード）と、採用パターンのお手本の掛け算式の**構造**を掛け合わせる（お手本の中身の丸パクリではなく構造の移植）
- **「お手本3人と自分の6項目」の表があれば、各案はお手本と①②か⑤⑥のどこかで違うこと。** ③どんなことを・④どのようにが同じなのは構わない（見たい人がいる証拠）。6つとも同じ案は上手な人の劣化版なのでボツ

### レポート生成

1. `assets/report_template.html` をベースにHTMLを生成する。デザイン（配色・フォント・角丸）はテンプレートのまま変えない。コンセプトカードを10枚、奇数は `class="concept"`・偶数は `class="concept alt"` で交互に並べる
   - ヘッダーの大見出しは**「あなただけのコンセプト案」で固定**。変えない
2. 保存先：`<対象者名>/05_コンセプト10案.html`
3. `open <ファイルパス>` でブラウザで開いてユーザーに見せる（Chrome拡張のnavigateは file:// URLに非対応＝httpsを前置してしまうので使わない。2026-07-29実機確認）
4. チャットには10案のタイトル一覧だけを番号付きで書き、「気になる番号を教えてください（複数OK）」と伝える。カードの中身をチャットに再掲しない

## Step 3：対話ブラッシュアップ → 決定版

ユーザーが選んだ案（複数可）を、勝ち筋の5判断材料（①自分の強み ②続けられること ③届けたい相手 ④売りたい商品・サービス ⑤今のアカウントの状態）で磨き、最後に「どんな未来へ」（6項目の⑥・任意）を決める。**質問は1問ずつ**。決まったら、6行のコンセプト（講座STEP5の6項目）に書き出して本人に声に出して読んでもらい、引っかかった行を直す。

1. **自分の強みが乗っているか** — 掛け算式に入れた特徴が、この人の実際の強み・実績・性格と一致しているか。盛った特徴・演じるキャラは続かない
2. **続けられるか・始められるか** — 「これ、週に何回・1回何分ならできそうですか？」現実の生活に置いてみる。無理なら負荷を下げた変形案を出す。決定前に「フォロワー0の今日、最初の1本を撮れるか」と、**継続チェック2問**＝「これは生活導線上にあるか（どうせ毎日やることのついでに撮れるか）」「100投稿できるイメージが湧くか」も必ず確認する
3. **届けたい相手に刺さるか** — 初期設計の「誰の・どんな悩み」とズレていないか照合する
4. **売りたいものにつながるか** — コンセプトが面白くても商品・サービス・ゴールへの導線が無ければ勝ち筋ではない。接続の形を一緒に設計する（投稿で戦うジャンルと収益化するジャンルは同じでなくていい。`03_ジャンル選定.md` の収益化導線があれば土台にする）
5. **今のアカウントの状態と合うか** — すでに運用中なら、既存の投稿・フォロワーを活かすのか仕切り直すのかを確認する。ゼロからなら飛ばしてよい
**最後に：どんな未来へを決める（任意）** — 講座STEP5の6項目の⑥。運営者の方針は「プロセスエコノミー型」（目標に向かう途中を見せて、続きを見に来てもらう形。例：「3ヶ月後に−5kg痩せる女」）。01の「これから進みたい未来」があれば出発点にして、無ければ1問ずつ聞く。**期限と期限の理由は分けて聞く**：
   - 「このコンセプトで、いつまでにどうなっていたい？」（期限）
   - 「なんでその時期なの？ その時期までに達成したい理由はある？」（期限の理由。例：結婚式までに・子どもの入学までに・40歳になるまでに）
   - 判定の目安：

   | 形 | 例 | 判定 | 次の一手 |
   |---|---|---|---|
   | 期限＋理由 | 3ヶ月後に−5kg（結婚式までに） | 強い。見る人が「間に合うのか」を追いかける | このまま6行の⑥に書く |
   | 期限だけ | 100日後に爆美女ボディを目指す | 弱め。なぜその期限なのかが無いので、続きを見る理由が本人の気分に頼る | 理由を聞いて足す。本当に理由が無ければ、期限を外して「進みたい暮らし」で書く方を勧める。本人が期限を残したいと言えば残してよい |
   | 期限なし | 無理なく節約を続ける暮らしへ | 弱くはない。ノウハウ型・暮らし型では普通の形 | 進みたい暮らしを1行で書く |

   - **⑥は必須にしない。** 期限を決めたくない人、プロセス型が合わないジャンル（例：レシピ・片づけのコツのように、毎回の投稿だけで役に立つ発信／終わりの無い暮らしの記録）では、期限を付けずに進みたい暮らしだけを書く。本人が「期限は決めたくない」と言ったらそれで決定
   - 期限の理由はAIが作らない。本人の言葉だけを使う
   - 期限と数字は本人がやれる範囲にする。体重・お金・体に無理がかかる約束（短期間で大きく痩せる等）は勧めず、「その期限で本当にできそう？」を1回確かめる。期限が来たら、結果も含めて見せるのがプロセス型だと伝える

磨き方の道具：
- **掛け合わせ**：「3番の企画性×7番の続けやすさ」のように2案を合成する
- **極端化**：「もっと極端にすると？」で制限や縛りを一段強くする
- **具体化**：最初の投稿3本のイメージまで落とすと、ユーザーは「やれるかどうか」を判断できる

ユーザーが「これでいく」と決めたら、成果物を保存する：

### 06_決定版コンセプト.md（このスキル唯一の成果物）
- コンセプト名＋キャッチコピー
- **6行のコンセプト**（講座STEP5の6項目と同じ並び。2026-11-04 追加）
  - ①誰が（属性）:
  - ②誰が（生い立ち・経験）:（本人が飛ばした所は書かない）
  - ③どんなことを:
  - ④どのように:（企画・見せ方・ビジュアル・世界観）
  - ⑤何が解決できるか:（誰の、どんな困りごとを解決して、何が手に入るか）
  - ⑥どんな未来へ:（型＝期限＋理由／期限だけ（本人の希望。理由は今後足す）／期限なし。期限：／期限の理由：）
  - ひと息の1文:（6行をつなげて「何のアカウント？」にひと息で答える形。並べる順は話しやすい順でよい）
- 誰の・どんな悩みを・どう解決するか（磨き上げ後）
- 差別化ポイント（＝あえてどんな面倒を引き受けて他と差をつけるのか）

## 言葉遣いのルール（insta-concept-design と共通）

- **専門用語を出力に使わない。** ペルソナ→「届けたい相手」、CTA→「行動のお願い」、ポジショニング→「立ち位置」など必ず日本語に言い換える
- **硬い敬語を使わない。**「させていただきます」ではなく「していきますね」。オトラボの講師が受講生に話すフレンドリーなトーン
- **数字を徹底的に集める。** 数字（kg・円・年・回数）がコンセプトとプロフィールの強さを決める。数字の気配がある回答には「数字でいうと？」と追い質問する
- レポートやチャットで理論を語りすぎない。理論はカード1枚のサマリーで十分。主役はコンセプト案

## 出す前の書き癖チェック

成果物の文章を出す前に、下の問いで自分の文を見直してから渡す。手順の中身は変えない。特別なファイルやプログラムは要らない（Mac・Windowsどちらでも同じようにやる）。

- **見直す文**：渡すHTMLレポートの文章
- **見直さない物**：表の数字・コード・ファイル名、文字起こし、参考投稿の引用、ユーザーが書いた原文。これらは書き換えずにそのまま残す（ただし表の数字と本文の数字が食い違っていないかは、問い5で見る）。題名・回の名前・商品名のように、目次や他の回・サイトとつながっている名前も勝手に変えず、直したいときはユーザーに聞く
- **いつ**：成果物を出す前に、全体を1周＋直した所の確かめ。途中の返事・確認の質問・作業の報告には当てない
- **スキルの決まりが先**：このスキルが決めている口調（話し言葉・方言・コーチの口調など）・改行・文字数・見出しの形・絵文字、そして台本や文面の型（締めの決まり文句・余韻や「つづく」の締め・わざと繰り返す言葉・気持ちをそのまま言う独白・問いかけ・必ず残すと決めた注記や欄）は、下の問いより先に守る。問いで見るのは、意味が伝わるか・事実が正しいかだけ

### 見直しの問い（20）

問いには2種類ある。**［全部］**は台本・ストーリーズ・報告書のどれにも当てる。**［説明］**は報告書・設計書・指摘文・改善案のような、何かを説明する文だけに当てる（台本・ストーリーズの文面には当てない）。

**名前と番号**
1. ［全部］最初に付けた呼び名を、最後まで同じ名前で使っているか。1つの言葉で2つの別の物を指していないか
2. ［全部］①②…や「1つ目・2つ目」の番号が、別々の物にかぶっていないか。番号は出てくる順に1から振ってあるか
3. ［全部］初めて読む人が何のことか分からない言葉が、説明なしで出ていないか。「さっきの例」「前の回で話した」のように、前の話を覚えている前提で書いていないか。「書き出した10個」「決めた場所」のように、この文章の中で作っていない物を、もうある物として指していないか。見出し・図の札・矢印の横の短い一言も含めて上から読み、札の「これ」「それ」は札が置かれた位置から読んで何を指すか分かるかで確かめる。人を記号で呼ばず、中身で呼んでいるか（例：「夜しか撮影できない会社員」）

**事実と数字**
4. ［全部］数字・出来事・セリフは、ユーザーの発言、渡された材料、このスキルが作ったファイルのどれかにあるか。どこにも無い物は書かない。どうしても要る時は〔要確認〕を付けてユーザーに聞く。文字数・枚数・秒数のように数えられる物は、書く前に実際に数える（「〜なら大丈夫」とぼかさない）
5. ［全部］同じ物の数字・期間・回数が、場所によって違っていないか（例：「3ヶ月」と「半年」）。数字だけでなく、前の段落や別の欄で言い切ったことと、あとの文が食い違っていないか（例：「やらなくていい」と言ったあとで、それをやった例を出す）。「〜しなくてよい」「〜だけでいい」と言い切った所は、後ろの段にそれを打ち消す例が出てこないかを最後まで追う
6. ［全部］「誰も」「必ず」「絶対」「〜しかない」と言い切った文に、当てはまらない例を1つでも思いつけるなら、条件を付けて言い直す。台本・文面の話し言葉でも、体・肌・お金・効き目について「〜する」「〜しない」「〜が残る」と言い切った所は同じ。言い換えのついでに、元に無かった言い切りを足さない
7. ［全部］その仕事やジャンルの経験者（美容師・飲食店の人・子育て中の親など）が読んで、直したくなる所はないか。道具やアプリの使い方、手間や値段の比べ方、届くまでの日数などが、現実のやり方と合っているか。よく知らない道具や仕組みは名前を書かず、ユーザーに聞く
8. ［説明］数字を出したら、それが読む人にとってどういうことか（多いのか少ないのか、何と比べてか、だから何をするのか）を同じ所で言っているか。数字だけを置いて先へ進んでいないか

**理由とつながり**
9. ［説明］言い切った文のそばに、そう言える理由があるか。「AだからB」「Aと言い直すとBになる」のAからBへの一歩を、読む人が自分で踏めるか（自分で別の例を1つ作り、同じ言い直しができるか試す。できないなら、間の一歩を文で足す）。「ので」の前が、結論を言い換えただけになっていないか。すぐ後ろで別の仕組みを説明しているなら、そちらが本当の理由なので、理由の文をそちらに合わせる。1つの結論に理由が2つ以上あるなら食い違っていないか。見出しと本文で、原因の説明が別々になっていないか
10. ［説明］ひとまとまり（1つの段落・1つの欄）で言いたいことは1つか。2文目・3文目は、1文目を読んだ人が次に聞きたくなること（理由・その先どうなるか）に答えて話を進めているか。事実を1行ずつ並べて終わり、行と行の関係を読む人任せにしていないか
11. ［全部］見出しと本文で、言っていることが同じか。比べる2つが同じ物差しで並んでいるか（片方は2つの組み合わせ、もう片方は3つ、になっていないか）。主語と述語がかみ合っているか（「見せ方が埋まる」のように、何が何をしたのか読めない文になっていないか）。言葉が途中で抜けて、意味が取れなくなった文はないか（短い札や実況の言い切りは問題にしない）

**話し方**
12. ［全部］1本の中で、話し方が途中で入れ替わっていないか（です・ます と だ・である、標準語と方言、話し言葉と書き言葉）。告知の枚・お願い・DMの締めだけ、急にかしこまった言い方やお店の決まり文句に変わっていないか。スキルが話し方を決めているなら、始めから終わりまでそれで通す。ただし揃えるのはスキルが決めた範囲だけ。お礼・お詫び・独白・締めの一言で、わざと違う言い方をしている所まで平らにしない
13. ［全部］ひねった言い方や作る側だけが分かる言葉（「角度」「解像度」「横断して」など）を、まっすぐな言い方にしたか（例：「この人に向けて作ります」）。人や物ではなく、雰囲気の言葉（「この景色」「あの日の自分」「ブランドの想い」など）が文の頭に立って、詩のようにまとめた文はないか（その場で目に見える物・人の動きで書く）。たとえ話を出したら、すぐあとで本当の言葉（実際の画面・物・数字）に言い直し、そのあとの段落や枚までたとえを使い続けていないか。本文に「下書き」「確認用」のような作業のメモが入っていないか
14. ［全部］読む人にお願いする文（登録して・保存して・待機して・コメントして）に、なぜ今それをやるのか（やらないと何が困るか、やると何が楽か）が、その文か近くに添えてあるか
15. ［全部］参考や見本から借りたのは組み立て（順番・長さ・間の取り方）だけか。スキルが「残す」と決めた型の外で、参考の言い回しをそのまま、または語尾だけ変えて使っていないか。その文の中身を、この人が話したどの一言・渡されたどの材料から取ったか言えるかで確かめる

**読む人への向き方**
16. ［説明］「このあと説明します」「ここからが大事です」のように、次の話を予告するだけの文はないか。その文を抜いて読み直しても話が通じるなら消す。同じことを言い直しているだけの所は、1つにまとめる
17. ［説明］読む人の頭の中を言い当てる文（「〜と思っていませんか」「〜で止まりがちです」）や、持ち上げるだけの文（「さすがの着眼点です」）はないか。言いたい中身があるなら、何ができているかを実際の数字や画面の言葉で書く
18. ［説明］改善案や「こうするといい」の文は、画面に何が映るか・誰が何をするかまで書いてあるか。「いい雰囲気に」「前向きに」「伝わるように」で止まっていないか

**並べたときと締め**
19. ［全部］何本・何枚も並ぶ物（ストーリーズの各枚、台本や案の一覧、各回・各章の書き出し）を続けて読んで、書き出しや締めが同じ言葉・同じ形のくり返しになっていないか。同じお願い・同じ決まり文句の締めが続くなら、何枚かは中身（新しい事実・次にやること）で終える
20. ［説明］最後の段落に、読んだ人が次にやること（どこを開いて何をするか）が書いてあるか。「頑張りましょう」「きっと伝わるはず」だけで終わっていないか

### 当てはまった文の直し方

- 直す前に、その文がスキルの決まりで「そのまま」とした欄・締め・独白・ほめ言葉に入っていないかを先に見る。入っていれば、事実の誤り以外は触らない
- 直す前に、その行・その枚が何のためにあるか（怖がらせる・買ってもらう・次を待ってもらう・ほめる）を1行で言う。消すのは間違いだけ。直したあとの文が、元の文の役目（ほめる・背中を押す・怖さや期待の山を作る・言い切って決めさせる）をまだ果たしているかを確かめる。言い切りを「〜しやすい」「〜かもしれません」に弱めて済ませない
- その文は捨てて、伝えたいことを1行で言い直してから新しく書く。似た言葉に入れ替えるだけ・後ろに言葉を足すだけで済ませない（文の「誰が・何を・どうする」を1行で言えないときも同じ）。伝えたい中身が無い文は消す
- 図の札・短い一言は、指す物を取り違えるときと事実が違うときだけ直す。別の段の話や、書かなくても分かる前提を札に足さない。気分を上げる一言を、すぐ上と同じ説明に置き換えない
- 名前・番号・数字のずれは、最初に決めた1つに**全文で**揃える（1か所だけ直すと、別の場所とまたずれる）
- 材料が足りなくて正しく書けない事実は、作らずにユーザーに聞く。確かめが取れない行も、消したり空欄にしたりせず、残したまま〔要確認〕を付ける（手本の行・冒頭の引きのように役目のある行は特に）
- 直した文とその前後だけ、もう一度問いを当てる。直したことで新しいずれが出ていないかを見る。もう一度直し直すときは、前に直した所の一覧と照らし、理由なく元に戻った所が無いかを確かめる

### 出すとき

成果物を出し終えたあと、返事のいちばん最後に1行空けて、次の1行を添える。報告書・台本・文面の中には書かない。

`書き方の見直し：◯か所直しました（名前のずれ・数字の食い違い・意味の取れない文など）`
