# concept-brush-up｜コンセプト磨き上げ

## このスキルについて

**コンセプトを1つに決めるのは、4スキル連携の中でこのスキルだけ。**

```
insta-concept-design Phase1-2（自己分析・ジャンル候補10／決めない）
   → genre-sentei（ジャンル確定） → concept-research（企画を裏取り）
   → concept-brush-up（本スキル・★決定版コンセプトを決める）
   → insta-concept-design Phase3（アカウント名・プロフィール）
```

流れは3ステップ：

1. **引き継ぎ** — 前工程の成果物を読み込む
2. **10案提案** — 差別化コンセプト10案をHTMLレポートでChromeに表示
3. **磨き上げ** — 対話でブラッシュアップして、決定版コンセプトを1つ決める

コンセプト生成の前に、必ず `references/raku-shinai-theory.md` を読むこと。理論の4ステップ・発想パターン7分類・勝ち筋の5判断材料がこのスキルのエンジン。

### Phase 2 の「ジャンル候補10」との違い（混同しない）

どちらも10枚だが、**粒度も目的も別物**。受講生に聞かれたらこう説明する。

| | insta-concept-design Phase 2 の10枚 | このスキルの10案 |
|---|---|---|
| 何を並べるか | 発信**ジャンル**の候補（枠） | ジャンル内の**差別化コンセプト**（中身） |
| 元になる情報 | 自己分析の素材だけ | 確定ジャンル＋市場リサーチの裏取り結果 |
| 決めるか | **決めない**（気になるものを2〜3個選ぶだけ） | **決める**（決定版を1つ） |
| 例 | 【作り置き・冷凍ストック】日曜3時間で平日5日を終わらせる | 「日曜3時間で5日分」を軸に、失敗した作り置きも全部出す少数派ポジション |

**起動時に必ず最初にやること**

1. `<対象者名>/00_state.md` を探して読む。あれば現在地・待ち状態・確定事項がすべて分かる（他のファイルを総なめしない）
2. 無ければ**旧形式のフォルダ**を探す（`<対象者名>_<日付>` `<対象者名>_リサーチ_<日付>` `<対象者名>_ジャンル選定_<日付>`）。見つかったら中身を読んで作業は続行し、**1つのフォルダに寄せてよいかユーザーに確認してから**移す。確認なしに移動・削除しない
3. それも無ければ新規作成する

**終了時に必ずやること**：`00_state.md` を更新する（決定版コンセプト・次にやること・申し送り）。

## Step 1：引き継ぎデータの読み込み

`00_state.md` を読んでから、次の優先順で読む：

1. **`04_リサーチ.md`（concept-research の成果物）が最重要。** 「ターゲット定義／企画候補トップ3／本人が選んだ方向／採用パターン／独自性素材／4要素突出診断」を引き継ぎの中心に据える。リサーチ済みの人はここが一番濃い素材
2. **`03_ジャンル選定.md`（genre-sentei の成果物）**。「確定ジャンル／判定の数値根拠／収益化導線／準備期間プラン／見送った候補と理由」を読む。**10案は確定ジャンルの中で出す**（ジャンルを聞き直さない・ジャンル外の案を出さない）。収益化導線は Step 3 の「売りたいものにつながるか」と 06_決定版の「収益化への道すじ」の前提にする
3. **`01_自己分析レポート.md`**（独自性素材シート＝掛け算式・ギャップ・エピソード／数字の武器）
4. **`02_ジャンル候補10.md`**（本人が選んだ候補と、「これは無理」と言ったもの。**蒸し返さない**）

あるものだけ読めばよい。無い場合の対応：

- Webアプリの書き出しファイル `~/Downloads/インスタアカウント設計書*.md`（複数あれば最新）を探し、あれば `<対象者名>/01_自己分析レポート.md` として保存して使う
- それも無ければ、最低限のヒアリングをする：発信ジャンル／届けたい相手／自分の強み・実績（数字で）／売りたいもの・ゴール／続けられそうな作業量。**1問ずつ聞く**こと
- **リサーチ（04）もジャンル選定（03）も無いまま10案を出す場合は、その旨を必ず伝える。**「今は自己分析の情報だけで出しているので、市場の裏取りはできていません。数字で確かめるなら genre-sentei → concept-research を先に通せます」

引き継いだら「誰の・どんな悩みを・どう解決するか」「数字の武器」「確定ジャンル」「選んだ企画の方向・採用パターン」を2〜3行で要約してユーザーに見せ、ズレがないか確認してから次へ進む。

## Step 2：差別化コンセプト10案 → HTMLレポート

### 10案の作り方

`references/raku-shinai-theory.md` を読んだ上で、ユーザーのジャンル内で成立する「差別化コンセプト」を10案作る。

- **発想パターン7分類のうち最低5パターンに散らす**。10案が全部「継続実況」のような偏りは禁止。カードにパターン名をタグ表示する
- 各案は記事の型（コンセプト／伸びる理由／人に教えたくなる理由）＋**勝ち筋との相性**（この人の強み・数字・売りたいものとどう接続するか）の4点で書く
- 引き継いだ**数字の武器を必ず使う**。「−36kg」「106kg時代」のような実数がキャッチコピーに入ると強い
- 「本当にやってるの？」「自分には無理だけど見たい」「友達に送りたい」のどれかを起こせない案はボツにして作り直す
- **フォロワー0人の初日でも始められる案にする。** 受講生の多くはゼロからのスタート。フォロワーの投票・コメント頼みの参加型や、お客さん・依頼者・生徒が必要な企画は、「誰に頼めばいいの？」で初日に手が止まる。ただし企画自体を捨てるのではなく、**手が届く相手に変換する**：「人の家を片付ける」→「友人の家を片付ける」のように、友人・同僚・後輩・家族で完結する形に直すと、受講生が具体的にイメージできる強い案になる。誰を巻き込むか（友人・同僚など関係性）を必ずカードに書く
- 現実的な負荷の幅をつける：全案が「毎日3時間かかる企画」だと選べない。軽め〜重めを混ぜる
- **`50-concepts-list.md` は配布禁止（他社記事の要約）。ここの案・言い回しを、受講生に見せる出力やWebアプリのプロンプトに書き写さない。** 受講生に見せてよい引き出しは `concept-examples.md` の200例だけ（2026-09-03の検証で混入事故があった）
- `references/concept-examples.md` のジャンル別200例は引き出しであって答えではない。ジャンルにそのまま近い案の流用は1〜2案まで。残りはこの人の職業・生活・性格からしか出てこない固有の案にする

### 04_リサーチ.md がある場合の追加ルール（2026-07-29）

リサーチ済みの人の10案は「机上の発想」ではなく「裏取り済みの市場」から作る：

- **企画候補トップ3・採用パターンに沿った案を10案の中心にする。** リサーチと無関係な思いつき案は多くても2〜3案まで（市場の外のワイルドカード枠として明示する）
- **各案に「掛け算式」と「ギャップ」を必ず明記する**：「特徴A(◯人に1人)×特徴B(◯人に1人)＝◯万人に1人／ギャップ：◯◯なのに◯◯」。目標は1,000万〜1億分の1（insta-concept-design と同じ基準）。カードの項目として追加する。掛け算もギャップも書けない案はボツ
- **各案に「どの要素で100点を取る案か」を付記する**（世界観／企画力／編集力／独自性のどれで突出する案か。全要素そこそこの案は伸びないのでボツ）
- **落とし穴3チェックを通す**：①テーマがバラバラにならないか ②その方向でうまくいっている実在アカウントが確認済みか・届けたい相手に矛盾がないか ③流行遅れの型をそのまま使っていないか（使うなら補強要素を明記）
- リサーチの独自性素材（本人の掛け算式・ギャップ・エピソード）と、採用パターンのお手本の掛け算式の**構造**を掛け合わせる（お手本の中身の丸パクリではなく構造の移植）

### レポート生成

1. `assets/report_template.html` をベースにHTMLを生成する。デザイン（配色・フォント・角丸）はテンプレートのまま変えない。コンセプトカードを10枚、奇数は `class="concept"`・偶数は `class="concept alt"` で交互に並べる
   - ヘッダーの大見出しは**「あなただけのコンセプト案」で固定**。変えない
2. 保存先：`<対象者名>/05_コンセプト10案.html`
3. `open <ファイルパス>` でブラウザで開いてユーザーに見せる（Chrome拡張のnavigateは file:// URLに非対応＝httpsを前置してしまうので使わない。2026-07-29実機確認）
4. チャットには10案のタイトル一覧だけを番号付きで書き、「気になる番号を教えてください（複数OK）」と伝える。カードの中身をチャットに再掲しない

## Step 3：対話ブラッシュアップ → 決定版

ユーザーが選んだ案（複数可）を、勝ち筋の5判断材料（①自分の強み ②続けられること ③届けたい相手 ④売りたい商品・サービス ⑤今のアカウントの状態）で磨く。**質問は1問ずつ**。

1. **自分の強みが乗っているか** — 掛け算式に入れた特徴が、この人の実際の強み・実績・性格と一致しているか。盛った特徴・演じるキャラは続かない
2. **続けられるか・始められるか** — 「これ、週に何回・1回何分ならできそうですか？」現実の生活に置いてみる。無理なら負荷を下げた変形案を出す。決定前に「フォロワー0の今日、最初の1本を撮れるか」と、**継続チェック2問**＝「これは生活導線上にあるか（どうせ毎日やることのついでに撮れるか）」「100投稿できるイメージが湧くか」も必ず確認する
3. **届けたい相手に刺さるか** — 初期設計の「誰の・どんな悩み」とズレていないか照合する
4. **売りたいものにつながるか** — コンセプトが面白くても商品・サービス・ゴールへの導線が無ければ勝ち筋ではない。接続の形を一緒に設計する（投稿で戦うジャンルと収益化するジャンルは同じでなくていい。`03_ジャンル選定.md` の収益化導線があれば土台にする）
5. **今のアカウントの状態と合うか** — すでに運用中なら、既存の投稿・フォロワーを活かすのか仕切り直すのかを確認する。ゼロからなら飛ばしてよい

磨き方の道具：
- **掛け合わせ**：「3番の企画性×7番の続けやすさ」のように2案を合成する
- **極端化**：「もっと極端にすると？」で制限や縛りを一段強くする
- **具体化**：最初の投稿3本のイメージまで落とすと、ユーザーは「やれるかどうか」を判断できる

ユーザーが「これでいく」と決めたら、成果物を保存する：

### 06_決定版コンセプト.md（このスキル唯一の成果物）
- コンセプト名＋キャッチコピー
- 誰の・どんな悩みを・どう解決するか（磨き上げ後）
- 差別化ポイント（＝あえてどんな面倒を引き受けて他と差をつけるのか）
- **尖りの根拠**：掛け算式（特徴A×特徴B＝◯万人に1人）＋ギャップ（◯◯なのに◯◯）＋どの要素（世界観/企画力/編集力/独自性）で100点を取るか。リサーチ済みなら裏取り済み企画・採用パターンへの言及も
- 人に教えたくなる瞬間の設計
- 最初の投稿3本の案
- **収益化への道すじ**：投稿（リール）で人を集めるジャンルと、収益化したいものは同じでなくていい。投稿で人を集め、ストーリーズ・ハイライトで売りたいものへの興味を育てる、という2階建てで書く（`03_ジャンル選定.md` の収益化導線があれば引き継ぐ）
- **継続チェック2問の答え**：生活導線上にあるか／100投稿できるイメージが湧くか（Step 3で確認した内容）

### 保存したあとの案内

`00_state.md` の「決定版コンセプト」を更新してから、次の一歩を案内する：

- **アカウント名・プロフィール** → `insta-concept-design` の Phase 3。決定版コンセプト・掛け算式・数字の武器を読んで作るので、ここで初めて一発で決まる（2026-09-03 に順番を最後尾へ移動。それ以前は先に作ってコンセプト確定後に作り直しになっていた）
- **リール台本** → `daihon-*` 系スキル

**このスキルではプロフィール文を作らない。** Phase 3 の担当（旧 `06_プロフィール改善案.md` は廃止）。現行プロフィール文を聞いていたら、`06_決定版コンセプト.md` の末尾に「## 現行プロフィール（Phase 3 への申し送り）」として貼っておく。

## 言葉遣いのルール（insta-concept-design と共通）

- **専門用語を出力に使わない。** ペルソナ→「届けたい相手」、CTA→「行動のお願い」、ポジショニング→「立ち位置」など必ず日本語に言い換える
- **硬い敬語を使わない。**「させていただきます」ではなく「していきますね」。オトラボの講師が受講生に話すフレンドリーなトーン
- **数字を徹底的に集める。** 数字（kg・円・年・回数）がコンセプトとプロフィールの強さを決める。数字の気配がある回答には「数字でいうと？」と追い質問する
- レポートやチャットで理論を語りすぎない。理論はカード1枚のサマリーで十分。主役はコンセプト案
