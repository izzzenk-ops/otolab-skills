# アフィリエイト訴求のストーリーズ（stories-affiliate）

商品を**理解してから**、多角的に訴求するストーリーズを設計する。

## 大前提

- **訴求の型は拡声器。**声を大きくする道具であって、声そのものではない。信用があるところに型を足すと伸びる
- **同じ商品でも、買う理由は人によって違う。**1つの角度だけで話すと、刺さらない層がまるごと残る
- 土台（日々の発信）は `stories-days` が担う。このスキルはプレプレを持たない

## 出力先

```
~/Documents/Claude/Projects/ストーリーズ作成/
├ 商品カルテ/<商品名>.md
└ ローンチ/<商品名_訴求日>/
   ├ カレンダー.md
   └ <日付>/文面.md ／ frames.js ／ photos/ ／ png/
```

---

## 最初に：訴求日と、取れる期間を聞く（★毎回いちばん最初）

商品URLを読む前に、これだけ聞く。
> 「訴求する日（リンクを出す日）は決まっていますか？ 今日からその日まで、どのくらい準備できますか？（おすすめは3週間＋10日）」

決まっていなければ「おまかせ」でよい（体験の量を聞いたあとで、こちらから日にちを提案する）。

## Phase 1：商品を理解する

### 初回（カルテが無い場合）

1. 商品URLをブラウザで開いて読み込む
2. `references/shohin_karte.md` の項目に沿って `商品カルテ/<商品名>.md` を作る
3. ★**ユーザーに見せて「この理解で合っていますか。訂正はありますか」と確認する**
   （誤読したまま数週間分を組むのがいちばん怖い）

### 2回目以降（カルテがある場合）

> 「この商品は以前（◯月◯日）このURLで調べています。前回の訴求構成もあります。**見ますか？**」

- 見る → カルテと前回のカレンダーを出す。変更点だけ聞く
- 不要 → そのままPhase 2へ

## Phase 2：ヒアリング

★**一度に聞くのは多くても5問まで。**1〜3を1回目、4〜5を2回目、6〜7（写真の3問と、見た目・文章の希望）を3回目のメッセージで聞く。分からない項目は「おまかせ」でよいと伝える。

1. **訴求日**（「最初に」で聞いたもの。変わっていないか確認だけ）
2. **期間**（1週間／2週間／3週間／**3週間＋10日（おすすめ）**／1ヶ月＋10日のどれで組むか。「最初に」の答えから当てはめる）
   - ★1週間を選んだら警告：「教科書の下限です。土台が積めないので、すでに温まっている人向けの短期戦になります」
3. ★**自分で使った経験を詳しく**
   - いつから使っているか／何がどう変わったか／**うまくいかなかった時期はあるか**
   - **そのときの気持ち**（使う前に何に困っていたか／初めて使った日にどう思ったか）
   - **Before → After**（何が、どのくらい変わったか。数字で言えるなら数字で）
   - 経験の量で、組み方を1本に決める（下の「体験の量で分ける」）
4. ★**Before素材をこの場で指示する**（カレンダー確定を待つと手遅れ）
   - 経験がない人 → 「**今日、使う前の写真を撮ってください**」＋撮る対象を具体的に指定
   - 経験がある人 → 「使う前の写真は残っていますか」を必ず聞く
5. **感想はあるか**
   - 無ければ促す：「友人に使ってもらう」「質問ボックスで感想を集める」「身内の反応でも十分」
6. **写真素材**（足りないものは撮影リストとして出す）。`references/common/shashin.md` の「まず聞く」3問も聞く
   - ★**商品の写真は、自分で撮ったものか公式・ASPの素材だけ。**AIで商品を作ると実物と違う写真になる
7. **文章の書き方とデザインの希望**（`~/Documents/Claude/Projects/ストーリーズ作成/設定.md` に記録が無ければ `stories-days` の STEP 1 と同じく聞く。ふだんの自分の文章を1つ貼ってもらうと口調を合わせられる）

### 体験の量で分ける（おまかせモードもここで決まる）

URLだけでも組み立てる。ただし**体験していないこと・聞いていない感想は書かない。**見本（ことね）の体験・数字・感想も流用しない。

| 体験 | 組み方 |
|---|---|
| ゼロ（まだ使っていない） | 「まず◯週間使ってください」と伝え、**使い始めから組む**。前半は体験の要らないカード（N教育枚・E権威・F思い込み反転）と「これから試してみる」実況、使い始めた日から「◯日目」の記録。**訴求日は試す期間のあとに置く**（試す前の訴求日は決めない） |
| 少しある | そのまま組む。足りない枚だけ **【ここにあなたの体験：◯◯を1〜2行】** と空けて、何を書けばいいかの問いを添える |
| たっぷりある | そのまま組む |

空欄が残る文面を渡すときは、最後に「空欄が残っている枚：◯枚目・◯枚目」と一覧で伝える。
細かい決まりは `references/common/sokyu_nagare.md` の「0. 聞き取り」。

## Phase 3：訴求角度カードを配る

`references/soukyuu_kado.md` を読む。

0. `~/Documents/Claude/Projects/ストーリーズ作成/発信軸.md` が無ければ、`stories-days` の STEP 0 と同じ5問で先に作る（**禁句3つは必須**）
1. 商品カルテ × 発信軸から**「買う理由」を5つ前後**洗い出す（時間／質／お金／見た目／健康／家族／将来 など。例は `references/common/sokyu_nagare.md`）
2. 買う理由ごとに、合うカードを割り当てる
3. **1日1角度**を基本に、期間ぶんのカードを並べる（2日で1角度も可：1日目＝問題提起／2日目＝解決）

⚠️ **同じ角度を3回続けない。**ただのしつこい人になる。

## Phase 4：カレンダーを組む

`references/soukyuu_kado.md` の「期間別カレンダー」に従って
`ローンチ/<商品名_訴求日>/カレンダー.md` を作り、**承認をもらう。**

守るルール（全期間共通）
- 匂わせの引っ張りは**2回まで**／待たせる理由を必ず添える
- **隠すのは商品名だけ**（9割分かって1割だけ分からない状態）
- 商品の話は**日常7割・商品3割**
- ★**「商品の話をしない日」を必ず挟む**（毎日商品の話をすると「またこれか」になる）
- 当日は**3枚以内にリンク**／**⑤未来を③④より先に出さない**／**最後の1枚をリンクにしない**

## Phase 5：各日の文面 → 承認 → 画像

1. カレンダーでその日のカードを確認
2. その日の出来事も聞いて混ぜる（商品の話だけにしない）
3. 文面を作る（`references/common/` の kakikae_7 / hitei_zurashi / neta_cho を当てる。
   ネタ帳ログ（`~/Documents/Claude/Projects/ストーリーズ作成/neta_log.md`）の直近30件を見て、同じ言い回しを繰り返さない）
4. ★**「この文面でいいですか？」で止まる**
5. 承認後に画像化。`references/common/gazou_seisei.md` の手順どおり（見た目＝デザインの希望 → 無ければ `design_kijun.md`／写真＝`shashin.md` の優先順／見せ方＝`hyogen_hikidashi.md`）
   ```bash
   python3 <このスキルのディレクトリ>/references/common/tools/render.py <日付フォルダ>/frames.js
   ```
   「#PR」は画像に入れない（投稿するときに本人が右上に入れる。入れる枚を文面.mdに書く）。`png/一覧.png` で全部の枚を見てから納品。リンク・スタンプは画像に描かず、文面.mdに「何枚目のどこに置くか」を書く。使った人の声は**本物のスクショをそのまま**貼る（DM風に打ち直さない）
6. `~/Documents/Claude/Projects/ストーリーズ作成/作成済み/_ログ.md` に `YYYY-MM-DD | affiliate | ...` と**用途タグ `affiliate`** を付けて記録。使った言い回しはネタ帳ログにも追記

## Phase 6：訴求日の直前チェック（★事故防止・1件目は必須）

- [ ] **ASPが発行したリンクを、開かずにコピーしましたか**
      （一度開いてアドレスバーからコピーしたURLだと、クリックが正しく計測されず成果が付かないことがある）
- [ ] **1件目だけ、担当者に「これで合っていますか」と確認しましたか**
- [ ] `references/soukyuu_kado.md` の「訴求当日の11項目」を当てたか

## Phase 7：訴求後

`references/common/sokyu_nagare.md` の「4. 感想集め」で感想を集めて、**角度を変えて**繰り返す。良いものは何度でも出してよい。
1回目＝時間の話／2回目＝質の話／3回目＝買った人の感想中心／4回目＝3ヶ月使ってどうだったか

## 質問回答型（G）が使えないとき

Gは訴求期間の主力だが、フォロワーが少ないと質問ボックスに何も来ない。そのときは：

1. 自分が質問する側に回る（送る側の緊張を知る）
2. **答えやすい質問にする**（「悩みがあれば何でも」ではなく2択スタンプ）
3. ★**想定質問を自分で作る**（「もし今から始めるとしたら」の形にすれば、質問が無くても成立する）

## 法令まわりの扱い（★重要）

「#PR」は**投稿するときに本人がインスタの画面で右上に入れる**（画像には入れない）。企業名を併記することもある（例：#PR #企業名）。企業から表記の指定があれば、そちらに従う。
表現は企業の指示・確認に従う。ただし**薬機法は投稿した本人にも適用される**ので、効く・治るなどの表現はフラグが立ったら企業に確認してから出す。

⚠️ **このスキルは可否を判定しない。フラグを立てるだけ。**
商品カルテの制約に該当しそうな表現には、文面.mdに `⚠️この表現は企業に確認` と印を付ける。
判定をスキルに任せると事故る。最終判断は人がやる。

## 環境メモ

依存は Google Chrome（または Microsoft Edge）と Python3 だけ。Mac・Windows どちらも動く。★Windowsではコマンドの `python3` を `py` に読み替える。商品ページの読み込みにブラウザを使う。
背景写真のAI生成は ChatGPT の有料プランがあるときだけ使う（`references/common/tools/gen_image.py --check` で確認）。無くても最後まで作れる。
