# ローンチのストーリーズ設計（stories-launch）

自分の商品を売る日から逆算して、8週間（約2ヶ月）のストーリーズを設計する。

## 大前提

**当日にうまく話すのではなく、当日にはすでに欲しくなっている状態を作る。**
仕込みをしないと、当日の1本の中で「原因の説明・共感・価値観・商品紹介」を全部やることになり、
枚数は20枚を超えて、しかも最後まで見てもらえない。

## 出力先

```
~/Documents/Claude/Projects/ストーリーズ作成/
├ 自分商品カルテ.md
└ ローンチ/<商品名_販売日>/
   ├ カレンダー.md
   └ <日付>/文面.md ／ frames.js ／ photos/ ／ png/
```

---

## 最初に：販売日と、取れる期間を聞く（★毎回いちばん最初）

商品の話より先に、これだけ聞く。
> 「販売日はいつですか？ 今日から販売日まで、ストーリーズで準備できる期間はどのくらいありますか？（おすすめは8週間＝約2ヶ月）」

答えを聞いたら、その期間でどう組むか（下の「期間が8週間取れない場合」の表）を一言で伝えてから、STEP 0へ進む。

## STEP 0：商品を深く聞く（初回のみ・★浅く聞かない）

`自分商品カルテ.md` が無ければ、必ずここから。表面的な機能ではなく、**なぜと誰**を聞く。
★**一度に聞くのは多くても5問まで。**1〜4・5〜7（商品の芯）と8〜11（材料）の3回に分け、答えを聞くたびにカルテに書き足す（途中でやめても、次は続きから聞ける）。分からない項目は「あとで」でよいと伝える。

1. 何を売るのか（形態・価格・提供期間・定員）
2. ★**なぜこれを作ろうと思ったのか**（きっかけ・原体験）
3. **誰の、どんな悩みを解決するのか**（悩みの言葉をそのまま。要約しない）
4. その人は今どうしているのか／何を試して、何がダメだったのか
5. 買った人はどうなるのか（3ヶ月後・1年後）
6. **これが向かない人は誰か**
7. ★**すでに教えた人・関わった人の結果はあるか**（プレプレローンチの主材料になる）
8. **商品のURL**（販売ページ・LPがあれば。無ければ説明の文章でいい）
9. **自分の体験と、そのときの気持ち**：作る前に何に困っていたか／作っていて迷ったこと／**うまくいかなかった時期**
10. **Before → After**（自分や、教えた人の。写真やスクショがあるか）
11. **感想**（DM・コメントのスクショがあるか。**本物のスクショだけを使う**）

### 話せることが少ないとき（おまかせモード）

URLや説明文だけでも組み立てる。ただし**体験していないこと・聞いていない感想は書かない。**
体験が入る枚は **【ここにあなたの体験：◯◯を1〜2行】** と空けて、何を書けばいいかの問いを添えて渡す。
細かい決まりは `references/common/sokyu_nagare.md` の「0. 聞き取り」。

⚠️ 「AIで効率化する講座です」で終わらせない。
**「どんな悩みを持った人が、AIで効率化して、どうなるのか」**まで聞く。ここが浅いと全部が薄くなる。

聞き終えたら `自分商品カルテ.md` に保存し、**「この理解で合っていますか」と1回確認する。**

## STEP 1：日程と条件を聞く

- 販売日と期間（「最初に」で聞いたもの。変わっていないか確認だけ）
- 発信軸.md はあるか（無ければ `stories-days` の STEP 0 と同じ5問。**禁句3つは必須**）
- **どこで売るか**：ストーリーのリンクから直接か、公式LINEを挟むか（`references/launch_calendar.md` の「売る場所」で一緒に決める）
- 今、質問スタンプやアンケートに**毎回何人くらい答えてくれているか**（少なすぎるならプレローンチを延ばす提案をする）
- 見た目と文章：`~/Documents/Claude/Projects/ストーリーズ作成/設定.md` に記録が無ければ `stories-days` の STEP 1 と同じく聞く（構成の参考／デザインの希望／文章の書き方の希望／文章だけか画像までか → 画像までなら `references/common/shashin.md` の3問／文字の量）

## STEP 2：カレンダーを組む

`references/launch_calendar.md` を読んで `ローンチ/<商品名_販売日>/カレンダー.md` を作る。

販売日をXとして、日数で区切る（期間が重ならないように）。
```
【プレプレローンチ】X-56〜X-29（4週間）★週2〜3回だけ
【プレローンチ】  X-28〜X-11（18日）信頼 → 距離 → 背中を押す
【ローンチ】      X-10〜X（興味づけ10日 → 当日）
【アフター】      X+1〜
```

⚠️ **プレプレ期間は毎日その話をしない。**週2〜3回だけ。残りの日はカレンダーに
「**days で通常運用**」と明記する（`stories-days` が担当する日）。

売る理由を**5つ前後**に分けて書き出し、カレンダーに「何回目の訴求で、どの理由を使うか」を割り振る（`references/common/sokyu_nagare.md` の「買う理由は人によって違う」）。

カレンダーは**枠と着地だけ**を決める。文面は書かない。
（先に全部書くと、その日の出来事が入らず嘘っぽくなる）

カレンダーができたら**承認をもらう。**

## STEP 3：各日の文面を作る

「今日の分作って」と言われたら：

1. カレンダーでその日の枠（段階・型・着地）を確認する
2. **その日の出来事を聞く**
3. 出来事 × その日の枠 で文面を作る（`stories-days` の STEP 5〜6 と同じ作り方）
4. **訴求当日だけは** `references/launch_calendar.md` の「訴求当日の7つの順番」を使う。見本（架空の発信者の15枚）は `references/common/mihon_kotone.md`
5. `references/common/` の kakikae_7 / hitei_zurashi / neta_cho を当てる
   （ネタ帳ログ（`~/Documents/Claude/Projects/ストーリーズ作成/neta_log.md`）の直近30件を見て、同じ言い回しを繰り返さない）
6. 文面を出して **「この文面でいいですか？」で止まる**
7. 承認後に画像化。`references/common/gazou_seisei.md` の手順どおり（見た目＝デザインの希望 → 無ければ `design_kijun.md`／写真＝`shashin.md` の優先順／見せ方＝`hyogen_hikidashi.md`）
   ```bash
   python3 <このスキルのディレクトリ>/references/common/tools/render.py <日付フォルダ>/frames.js
   ```
   `png/一覧.png` で全部の枚を見てから納品。リンク・スタンプ・カウントダウンは画像に描かず、文面.mdに「何枚目のどこに置くか」を書く
8. `~/Documents/Claude/Projects/ストーリーズ作成/作成済み/_ログ.md` に `YYYY-MM-DD | launch | ...` と**用途タグ `launch`** を付けて記録する。使った言い回しはネタ帳ログにも追記

## STEP 4：アフター（販売後）

`references/launch_calendar.md` の「アフター」と `references/common/sokyu_nagare.md` の「4. 感想集め」に従う。
感想は**スクショのまま**（名前とアイコンは隠す）・**良いことだけ選ばない**・**1枚に1件**。
集めた感想は次の訴求の材料になる。**角度を変えて**繰り返す。

---

## 期間が8週間取れない場合

| 取れる期間 | 削るもの |
|---|---|
| 6週間（42日） | プレプレを X-42〜X-29 の2週間に縮める |
| 4〜5週間（28〜35日） | プレプレを省き、プレローンチ（X-28〜X-11）＋ローンチ（X-10〜X） |
| 3週間（21日） | プレローンチを X-21〜X-11 の11日に縮める（信頼・距離・背中を押すを3〜4日ずつ）＋ローンチ |
| 2週間以下 | ★警告する：「土台が積めないので、当日の閲覧数が半分に落ちて返信ゼロになりやすいです」。日程を動かせないなら、目標の数を下げるか、公式LINEに来てくれた少人数に絞って売る案を出す |

## 出す前チェックリスト（訴求当日）

`references/launch_calendar.md` の10項目を必ず当てる（自分の商品なのでPR表記の項目は無い。企業から報酬を受けて紹介する場合は stories-affiliate の11項目）。
とくに ⑩「**売る瞬間だけ別人の言葉になっていないか**」。
普段「〜だと思ってる」と書いている人が、当日だけ「〜が実現できます」と書き始めると、見ている人は違和感を必ず感じ取る。

## 環境メモ

依存は Google Chrome（または Microsoft Edge）と Python3 だけ。Mac・Windows どちらも動く。★Windowsではコマンドの `python3` を `py` に読み替える。Notion未接続でも全部動く。
背景写真のAI生成は ChatGPT の有料プランがあるときだけ使う（`references/common/tools/gen_image.py --check` で確認）。人の顔・紹介する商品そのものはAIで作らない。無くても最後まで作れる。
