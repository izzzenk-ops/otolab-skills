# こえタイプ 導入

fnキーを1回押して喋り、もう1回押すと、AIが清書した文章がカーソル位置に入る音声入力ツール。
このスキルは、それを**使える状態にするまで付き添う**。

## 大前提

**「入れました」で終わらせない。** 実際に喋ってもらい、文字が入ったことを確認して初めて完了とする。
判断に迷ったら `setup.py status` を叩いて、今どうなっているかを事実で確かめる。

道具:

```bash
python3 ~/.claude/skills/koetype-setup/setup.py status       # いまどこまで進んでいるか
python3 ~/.claude/skills/koetype-setup/setup.py install      # アプリを取得して設置・起動
python3 ~/.claude/skills/koetype-setup/setup.py setkey <KEY> # APIキーを設定して疎通確認
python3 ~/.claude/skills/koetype-setup/setup.py restart      # アプリを再起動
python3 ~/.claude/skills/koetype-setup/setup.py lastresult   # 直前に喋った結果を見る
```

---

## Step 0. 今の状態を調べる

最初に必ず `status` を実行する。すでに途中まで進んでいることがある。

- `⚠ Apple Silicon専用` と出たら、**そこで止める。**「このMacでは動きません」と伝えて終わる。
  無理に進めない。Intel Macでは起動しない。
- `総合: すぐ使えます` と出たら、Step 4（動作確認）だけ行う。

## Step 1. アプリを入れる

```bash
python3 ~/.claude/skills/koetype-setup/setup.py install
```

インターネットから取得して `/Applications` に置き、起動するまでを自動で行う。

**「開発元を検証できません」の警告は出ない。** ブラウザ以外で取得しているため隔離の印が付かない。
もし警告が出たと言われたら、ブラウザで手動ダウンロードしていないか確認する。

## Step 2. 許可を3つもらう ← ここが一番つまずく

**3つとも必要。** 1つでも欠けると、症状が違う形で出る。

| 許可 | 無いとどうなるか |
|---|---|
| マイク | 録音しても無音になる（エラーは出ない） |
| 入力監視 | fnキーを押しても何も起きない |
| アクセシビリティ | 文章はできるのに貼り付かない |

**1つずつ**開いて、入れてもらったことを確認してから次に進む。まとめて頼まない。

```bash
open "x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone"
open "x-apple.systempreferences:com.apple.preference.security?Privacy_ListenEvent"
open "x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility"
```

**必ず「何のための許可か」と「何をしないか」を添える。** 特に「入力監視」は、画面に
「キーボードで入力した内容を監視・記録することを許可します」と出るので、説明なしに頼むと必ず手が止まる。

**スイッチを入れるとき、Macのパスワードか Touch ID を1回聞かれる。これも先に伝える。**

伝え方の例:

> いま「マイク」の画面を開きました。一覧の中の「こえタイプ」のスイッチをオンにしてください。
> 声を録るための許可です。Macのパスワード（またはTouch ID）を1回聞かれます。
> 済んだら「できた」と教えてください。

> 次は「入力監視」です。画面に「入力した内容を監視・記録する」と出て驚くと思いますが、
> **こえタイプが見るのは「fnキーが押された」ということだけで、打った文字の中身は読みません。**
> パスワードやカード番号の入力も対象外です。

> 最後は「アクセシビリティ」です。**できあがった文章を、カーソルの位置に貼り付けるための許可**です。

3つ終わったら:

```bash
python3 ~/.claude/skills/koetype-setup/setup.py restart
```

3つとも `OK` になるまで先に進まない。`未許可` が残っていたら、その画面をもう一度開いて確認する。

**一覧に「こえタイプ」が見当たらない場合**は、アプリが起動していない。`restart` を実行してから開き直す。

## Step 3. GeminiのAPIキーをもらう ← 罠が多いので慎重に

文字起こしと清書はGoogleのGeminiが行う。**無料枠だけで足りる**（1日500回・長さは関係なく回数で数える）。

**受講生に話すときは「Google（Gemini）」と言う。** 「Gemini」だけだと、一覧に書いてある「Google」と
別のサービスだと思われて「もう1個登録するの？」になる。

**先に、お金の不安を消しておくこと:**

> クレジットカードは要りません。無料のまま1日500回使えます。
> 使い切っても請求は来ません。しばらく待てばまた使えます。

### 案内の順番（この順を崩さない）

0. **先に「どのGoogleアカウントで取るか」を決めてもらう。** 仕事用と個人用を併用している人が多い。
   あとから別のアカウントで取り直すと別のキーになるので、最初に決めておく
1. https://aistudio.google.com/apikey を開いてもらう
2. そのアカウントでログインしてもらう（**ここは本人しかできない**）
3. **利用規約への同意画面が出たら、必ず本人に読んで判断してもらう。** 代わりに押さない
4. 「**API キーを作成**」を押してもらう
5. **プロジェクトを選ぶ画面が出たら**「**＋ プロジェクトを作成**」を選んでもらう ← **最重要**
   - **その画面が出ずにキーができてしまう人もいる。** Googleを初めて使うアカウントだと、
     規約に同意した時点でプロジェクトとキーが自動で作られる（公式にそう書かれている）。
     その場合はそのまま次へ進んでよい。自動で作られたプロジェクトには支払い情報が付いていないので問題ない
6. プロジェクト名を聞かれたら「**koetype**」でよいと言い切る（何でもよいが、迷わせない）
7. できたキーをコピーして貼ってもらう

**キーを貼ってもらうときに、必ずこう添える:**

> この文字列を私に貼ってください。**あなたのMacの中にだけ保存します。**
> 使うのはGoogleに文字起こしを頼むときだけで、他のどこにも送りません。

### 4番を必ず守らせる理由

**すでにあるプロジェクトを選ぶと、支払い情報が紐づいている場合に無料枠が使えず、
`429 prepayment credits are depleted` で一切動かない。** 見た目は成功するので気づけない。

「新しいプロジェクトを作る」を選べばこの問題は起きない。ここだけは念を押すこと。

### キーを受け取ったら

```bash
python3 ~/.claude/skills/koetype-setup/setup.py setkey <もらったキー>
```

**実際にGeminiへ1回投げて、本当に使えるかを確かめてから保存する。** 使えないキーは保存しない。
失敗したときは、原因と次の一手が日本語で表示されるので、それをそのまま伝えて対処する。

**キーはこの人のMacの中だけに保存される**（`~/Library/Application Support/KoeType/config.json`・本人のみ読める権限）。
どこにも送信されないことを伝えると安心してもらえる。

## Step 4. 実際に喋ってもらう ← ここまでやって完了

メモ帳など、文字を入力できる場所を開いてもらい、こう伝える:

> 1. 文字を入れたい場所をクリックしてください
> 2. **fnキー**（キーボードの左下の角、🌐マークのキー）を1回押します
> 3. 「ポン」と鳴ってから、2〜3秒なにか喋ってください
> 4. もう一度fnキーを押します
> 5. 数秒待つと、清書された文章が入ります

**「ポンが鳴ってから喋る」を必ず伝える。** 押した直後はマイクがまだ開いておらず、話し始めが切れる。

結果を確認する:

```bash
python3 ~/.claude/skills/koetype-setup/setup.py lastresult
```

`完了 ◯秒 / ◯文字` が出ていれば成功。使い方を一通り伝えて終わる。

## うまくいかないときの見分け方

`lastresult` の記録で原因が分かる。**推測で答えず、必ずログを見てから答える。**

| ログに出ていること | 原因 | 対処 |
|---|---|---|
| `キー検知` が出ない | 入力監視の許可がない／別のキーを押している | Step 2をやり直す。keycode 63がfn |
| `キー検知: keycode=63` は出るが録音しない | 押したキーと設定が違う | ログのkeycodeを `hold_key_code` に設定 |
| `声が入っていない` | マイクが違う／許可がない | メニューバーのアイコン →「マイク」から選び直す |
| `無料枠が尽きました` | Geminiの1日の上限 | **日本時間の夕方（16〜17時ごろ）**に戻る。自動で別モデルに切り替わる |
| `失敗` | 通信・API | メニューの「失敗した録音をやり直す」で再送できる |
| 何も記録がない | アプリが起動していない | `restart` を実行 |

**AirPodsを使っていて無音になる場合**は、AirPods側の問題。
メニューバーのアイコン →「マイク」から「MacBook〜のマイク」を選べば解決する。
（AirPodsはマイクを使う瞬間に通話モードへ切り替わるため、音が途切れたり拾えなかったりする）

## 伝えておくとよいこと

- **メニューバーのアイコン**を押すと、今の状態・マイクの選択・「言葉を覚えさせる」が使える
- **言葉を覚えさせる**: 一度直した表記は次から間違えない。1行1件で `ぽちぺた、ぽちペタ` のように書く。区切りは `、` でよい
- **10分喋っても大丈夫**（上限30分）。長さではなく回数で数えるので、長く喋る方が枠に優しい
- **1日500回を使い切っても、請求は来ない。** 枠が戻るのは**日本時間の夕方（16〜17時ごろ）**。
  「翌日」と伝えないこと（Googleは太平洋時間の0時にリセットするため、翌朝はまだ戻っていない）
- 500回という数字はGoogleの公式ドキュメントには載っておらず、AI Studioのレート制限画面で確認した値
  （ https://aistudio.google.com/rate-limit ）。値が変わっても告知されない
- **音声はGoogleにだけ送られる**。作者のサーバーは通らない。設定は自分のMacの中だけに残る
- **喋った内容の扱いは、導入のときに必ず伝える。** Googleの規約（ https://ai.google.dev/gemini-api/terms ）に、
  無料枠（Unpaid Services）で送った内容は**製品改善・AIの学習に使われることがあり、担当者が読むことがある**、
  **機密情報・個人情報は送らないこと**と明記されている。伝え方の例:

  > 喋った内容はGoogleに送られます。無料で使う場合、Googleはその内容を製品の改善に使うことがあり、
  > 担当者が読むこともあると規約に書かれています。**お客様の氏名や連絡先、外に出せない話は喋らないでください。**
  > 台本や下書きなど、いずれ公開するものを喋る分には問題ありません。
- fnキー以外にしたい場合は、`hold_key_code` を変えれば右Optionなどにもできる
