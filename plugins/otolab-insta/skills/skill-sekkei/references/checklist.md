# 最後のチェック（14項目）

設計書を出力する直前に、**1項目ずつ実際に設計書を見て** Yes/No で答える。
**Noが1つでもあれば出力しない。** 埋めきれないものは「12. まだ決まっていないこと」に落としてから出す。

これは「基準」ではなく「**探し方**」。読み流すと一度も引っかからない。

---

| # | 質問 | Noのときにやること |
|---|---|---|
| 1 | **起動の言葉**が5個以上あり、既存スキルとかぶっていないか確認したか？ | Phase 5 に戻る。かぶっていたら言い方を足す |
| 2 | 評価・採点・選抜が入るスキルなら、**「書いた本人に採点させない」**と**「Yes/Noの欠陥チェックリスト」**の両方が書いてあるか？（片方だけは不可） | 「7.」に2行とも書く。入らないスキルなら該当なしでYes |
| 3 | **合格の見本が、本文として貼ってあるか？**（ファイルの場所やURLだけになっていないか） | 本文を貼る。Phase 2 のお手本があれば流用する。**どちらも無いときは「9.」に「まだ無い」と書き、「12.」に「合格の見本を後で足す」を入れてYesとする**（見本が無いだけで設計書を止めない） |
| 4 | **必要な道具**が判定してあり、Windowsのとき・お金がかかるときの記載があるか？ | こちらが判定して埋める。相手に聞かない |
| 5 | **できあがる物の形と置き場所**が決まっているか？（チャットに出すだけなら「なし」でよい） | 「チャットに出すだけ」か「`Projects/<プロジェクト名>/` にファイルを置く」かを決める |
| 6 | **渡され方の分岐**（URL／ファイル／文章／何もなし）が全部埋まっているか？ | 空欄を埋める。「起きない」なら「起きない」と書く |
| 7 | **やらないこと**が1つ以上書いてあるか？ | Phase 7 のチェックボックスから最低1つ入れる |
| 8 | **完成の定義**が、目で見て判断できる形で書いてあるか？（「いい感じ」になっていないか） | 数えられる形に書き直す |
| 9 | 今あるスキルと**重ならないことを確認した記録**が「2.」に残っているか？ | Phase 0 の結果を1行書く。確認できなかったなら「未確認」と書く |
| 10 | **テストのしかた**（アプリ再起動を含む）が入っているか？ | ひな型の固定文をそのまま入れる |
| 11 | **「ここで一回見せて」と言う場所**が最低1か所あるか？ | 1か所決める。決まらなければ「最後にまとめて見せる」でも可 |
| 12 | 実際の数字・個人が分かる情報を外に出す可能性があるなら、**その注意**が「10.」に入っているか？ | 定型行を入れる |
| 13 | **「0. これを受け取ったClaudeへ」**の固定文（skill-sekkeiを起動しない／置き場所／evalsとパッケージ化をやらない／日本語descriptionをそのまま使う／12.を先に潰す／アプリ再起動を伝える）が6つとも入っているか？ | ひな型からそのままコピーする |
| 14 | **チャットに出すとき、外側のコード枠をバッククォート4つにしたか？** 貼り付けたとき「14. 完成の定義」まで枠の中に入っているか？ | 4つに直す。ここを外すとコピーが尻切れになり、受け取ったClaudeが後半を読めない |

## 通したあとに必ずやること

- 14項目すべてがYesでも、**「12. まだ決まっていないこと」が空のまま**なら、
  本当に全部決まったのかもう一度見る。たいてい1つは残っている
- 残っているものは「なし」と書かずに、正直に書いて次の会話に引き継ぐ
