# ヒアリングの質問文（Phase 0〜9）

ここに書いてある質問文をそのまま使う。要約しない。**1回の発言で聞くのは1つだけ。**

相手は非エンジニア。「分からない」と言われたら、こちらが仮案を出して○×にする。**詰まらせない。**

まず、いま入っているスキルと重ならないか確認します。
途中で「許可しますか？」と聞かれたら〈許可〉を押してください。

1. `~/Documents/Claude/Projects/スキル設計/*/00_state.md` を探す。
   あれば「〇〇の続きですか？」（複数あれば一覧で選ばせる）

## Phase 1｜ざっくり3問＋仮の名前

**1問ずつ。**まとめて出さない。

### Q1

```
いま、何にいちばん困っていますか？
毎回めんどくさいこと・時間がかかっていることを、1つ教えてください。
```

答えが出ないときの言い換え:
- 「毎週やっている作業を1つ教えてください」
- 「先週Claudeに頼んだことで、また頼みそうなことはありますか？」

### Q2

```
それを、どんなふうにスキルにしたいですか？
ざっくりで大丈夫です。うまく言葉にできなければ、さっきの困りごとから一緒に決めます。
```

**「スキルにできる粒度が分からない」で止まるのが一番多い。** 止まったら、Q1の答えから
こちらが2案出して選ばせる。例:
```
たとえば、こんな作り方ができます。どちらが近いですか？
A. 毎回同じ手順を最後まで自動でやる（例: URLを渡すと報告書が1枚できる）
B. 質問しながら一緒に作る（例: 何問か聞かれて、答えると文章ができる）
```

### Q3

```
それができたとき、何が出てきたら嬉しいですか？
```
選択肢を添える: 報告書（画面で見るもの）／文章（コピーして使うもの）／リスト・表／画像／
整理されたファイル／その他

### Q4（答えられる人だけ。答えられなければ飛ばす）

```
いまそれを人にお願いするとしたら、何て頼みますか？
```
※「今それを手でやるなら何をしますか」とは聞かない。手順を思い出せる人は少ない。

### 仮の名前を決める

```
作業フォルダを作りたいので、仮の名前をつけさせてください。
「<提案する名前>」でいいですか？　あとから正式な名前は変えられます。
```

- こちらが1案出して○×。相手に考えさせない
- 決まったら `~/Documents/Claude/Projects/スキル設計/<仮の名前>/` を作り、`00_state.md` を書く
  （`Projects/` や `スキル設計/` が無ければ一緒に作る。相手には報告しなくてよい）
- **このフォルダ名は以後変えない**（正式名が変わってもフォルダはそのまま）

## Phase 2｜お手本・元ネタの確認

**このスキルで一番大事なところ。** お手本が無いまま作ると、それらしいけど使えないものができる。

### Q1（参考URL）

```
お手本にしたいものはありますか？
「こういうのが作りたい」と思った投稿・記事・サイトがあれば、URLを貼ってください。
（いくつでもOK。無ければ「ない」で大丈夫です）
```

URLが出たら、**そのURLを毎回見に行くのか／中身を渡すのか**を決める。
Instagram・TikTok など**ログインしないと見られないもの**が来る確率が高い。そのときは相手に選ばせる:

```
このお手本、ログインしないと見られないページですね。
中身をどうやって渡しますか？
1. 文字（テロップ・キャプション）を書き写して貼る
2. スクリーンショットを渡す
3. 動画そのものを渡す（スキルの中で文字起こしする作りにする）
4. わからない → こちらで決めます
```

3を選んだ場合は「11. 必要な道具」に動画の準備が要ることを書く（Windowsは別手順になる）。

### Q2（手元のファイル）

```
参考にするファイルは手元にありますか？
1. ある
2. ない
3. わからない
```

- **「1. ある」→「ここにドラッグ＆ドロップしてください」。**「パスを教えてください」とは絶対に聞かない
- 「3. わからない」→ こちらが `~/Documents/Claude/Projects/` を探して、関係ありそうなものを3つまで出して選ばせる

### Q3（過去に作ったもの）

```
同じような作業を前にやったことはありますか？
そのときの結果が残っていれば、それが一番いいお手本になります。
```

### お手本が1つも無いとき

隠さずに伝える。ただし止めない:
```
お手本が無いままでも作れますが、「なんとなくそれっぽいもの」が出てくる確率が上がります。
どうしますか？
A. 先にお手本を1つ探してくる（おすすめ）
B. このまま進める（あとで足せます）
C. スキルの中で毎回探すところからやらせる
```

## Phase 3｜手順に分ける

**相手に手順を書かせない。こちらが割って見せる。**

Phase 1・2の答えから、3〜7個の手順に割る。**一度に全部見せない。1つずつ聞く。**

```
やることを手順に分けてみます。1つずつ確認させてください。

手順①「<やること>」
　渡すもの: <>
　出てくるもの: <>
これは要りますか？（要る／要らない／ちょっと違う）
```

- 「ちょっと違う」→ **代案を2つ出して選ばせる。**「どう違いますか？」と聞き返さない
- 全部の手順に「**ここまでできたら次へ進む**」を1行つける（例:「文字起こしのテキストができたら次へ」）
- 手順が8個を超えたら多すぎる。**まとめるか、スキルを2本に分ける提案をする**

最後に全体を並べて見せて、順番だけ確認する。

## Phase 4｜確かめ方と「一回見せて」と言う場所

**「何を見たらOKと言えますか」とは聞かない。答えられない。**

こちらが**目で見て数えられる合格ライン**を3案出して選ばせる:

```
手順①が「ちゃんとできた」と言えるのは、どれが近いですか？
A. 〇〇が5本以上出ている
B. 全部のURLが実際に開ける
C. 自分の口調で読める文章になっている
（全部でもOK。ほかにあれば教えてください）
```

**数えられる形にすること。**「質が高い」「いい感じ」は合格ラインにしない。

### 「ここで一回見せて」と言う場所

```
途中で一度、こちらに見せてほしいところはありますか？
たとえば「文章を書き始める前に、内容の案だけ見せて」みたいなところです。
1. 手順②が終わったところ
2. 最後にまとめて見る（途中では止めない）
3. わからない → こちらで決めます
```

**1か所は必ず入れる。** 全部自動で最後まで走ると、間違っていたときに全部やり直しになる。

### 評価・採点・選抜が入るスキルのときだけ、追加で伝えること

作ろうとしているスキルが「点数をつける」「良し悪しを判定する」「案を選ぶ」ものなら、
次の2つを設計書に必ず入れる（相手に聞かず、こちらが入れて説明する）:

1. **書いた本人に採点させない。** 同じ会話で書いたものを同じ会話で採点すると甘くなる
   （実測で35点差がついた例がある）。採点は必ず新しい会話でやる、と設計書に書く
2. **Yes/Noで機械的に通す欠陥チェックリストを、採点の直前に置く。**
   採点の基準（ルーブリック）だけでは足りない。「基準」はあっても「探し方」が無いと欠陥が見つからず、
   減点が一度も発動しない

## Phase 5｜起動の言葉

```
このスキルを使いたいとき、Claudeに何て言いそうですか？
かしこまらずに、いつもの言い方のまま3〜5個ください。
（例:「あれやって」みたいな短い言い方でもOKです）
```

### そのあと必ずやること

1. 集まった言葉を `~/.claude/skills/` の既存スキルのdescriptionと突き合わせる
2. **かぶっていたら伝えて、別の言い方を提案する:**
   ```
   「台本作って」は、いま入っている別のスキルが先に反応してしまいます。
   「〇〇用の台本作って」のように、一言足しませんか？
   ```
3. 5個に足りなければ、こちらが言い回しを足して10個くらいまで増やす（○×を取る）
4. **途中で中断して再開する作りのスキルのときだけ**、「**<スキル名>の続き**」も起動の言葉に入れる。
   1回で終わるスキルには入れない（押しても再開できない言葉が混ざる）

## Phase 6｜合格の見本

```
「こういうのが出てきたら大成功」というものを1つ見せてください。
・他の人の投稿・記事でもOK（URLでも、コピーして貼ってもOK）
・自分が前に作ったものでもOK
```

- **本文を貼ってもらうのを既定にする。** ファイルの場所（パス）だけだと、
  別の会話で読めないことがある
- 無ければ Phase 2 のお手本を流用する
- **「不合格の見本」は相手に出させない。** こちらが「こうなったら失敗」を3つ書いて○×を取る:
  ```
  逆に、こうなったら失敗だと思います。合っていますか？
  ・〇〇が入っていない
  ・△△が長すぎて読む気が失せる
  ・□□が毎回同じ言い回しになる
  ```

## Phase 7｜やらないこと

チェックボックス方式。**考えさせない。**

```
このスキルに「やらせないこと」を決めます。当てはまるものを選んでください（複数OK）。
□ 勝手に投稿・送信しない（必ず見せてから）
□ 勝手にファイルを消したり移動したりしない
□ 実際の数字や個人が分かる情報を、そのまま報告書に載せない
□ 頼んでいない改善案を付け足さない
□ その他（あれば）
```

3番目は、外に出す可能性があるものを作るスキルなら**既定でオンにする**。
